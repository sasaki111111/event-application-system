# 06_設計確定時の確認事項

## 1. 本書の位置づけ

`docs/01`〜`05`は、今後の開発における正式な要件・仕様の基準として作成した文書である。本書は、それらの文書を正式な基準として確定させるにあたり、関係者間の意思決定が必要な事項を記録し、決定後は該当する設計書へ反映するための文書である。

方針が確定した事項は「2. 確定した事項」に反映先とあわせて記録し、`docs/01`〜`05`の本文を更新する。未確定の事項は「3. 未確定事項」に記録する。

## 4. 実装側での対応が必要な事項

以下は、設計書の内容そのものではなく、設計書に定めた仕様と現在の実装を一致させるために必要な対応である。設計書は本書「2. 確定した事項」の内容をもって正式仕様として確定しているため、下記は実装側の追随対応として管理する。

| No | 内容 |
|---|---|
| I-01 | 画面側の管理者判定を、バックエンドが返す利用者区分（`role`）に基づく方式へ統一する（D-03）。実装済み。 |
| I-02 | 管理者アカウント登録機能（F-15／AP-25／SC-13）、参加区分名の一意制約（D-07）、CSV出力対象範囲の統一（D-06）、再チェックイン時の確認制御（D-05）を実装へ反映する。実装済み。 |
| I-03 | 同時申込時の排他制御（悲観ロック）を実装へ反映する（D-10）。実装済み。 |

## 5. 今後の確認事項の管理方法

新たに確認が必要な事項が生じた場合は「3. 未確定事項」に追記する。方針が確定した場合は「2. 確定した事項」へ移し、該当する設計書へ反映する。
