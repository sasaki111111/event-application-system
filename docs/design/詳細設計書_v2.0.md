## 3. 既存クラスへの変更点

| クラス | 変更内容 |
|---|---|
| `Event` | フィールド追加（§2）。`applyChanges()`にも新フィールドを反映。`ticketTypes`は`@OneToMany`で保持（保存時に全置換） |
| `Application` | フィールド追加（§2）。`checkIn()`メソッド新設（`checkedInAt = LocalDateTime.now()`を設定するだけの単純なメソッド、`softDelete()`と同じ設計方針） |
| `EventRepository` | `findAllByCategory...`等は不要（カテゴリ絞り込みはフロント側で行うため、既存の全件取得メソッドをそのまま使う） |
| `ApplicationRepository` | `countByTicketType_IdAndStatus(ticketTypeId, status)`、`countByEvent_IdAndStatusAndAppliedAtLessThan(...)`（順位計算用）を追加 |
| `EventService` | `create()`/`update()`で`ticketTypes`をあわせて保存する処理を追加。`toDetail()`に`ticketTypes`・`commentCount`を含める |
| `ApplicationService` | `apply()`の定員判定を区分単位に対応。`toMyApplicationResponse()`に`waitlistRank`計算を追加。`listAttendees()`・`checkIn()`メソッドを追加 |

## 4. 主要処理のシーケンス図（追加分）

### 4.1 イベント申込（区分ありイベント、機能追加）

```mermaid
sequenceDiagram
  actor U as 一般ユーザー
  participant FE as event-detail.ts
  participant C as ApplicationController
  participant S as ApplicationService
  participant ER as EventRepository
  participant TR as TicketTypeRepository
  participant AR as ApplicationRepository
  U->>FE: 区分を選んで「申し込む」
  FE->>C: POST /api/applications { eventId, ticketTypeId, extraAnswer }
  C->>S: apply(userId, eventId, ticketTypeId, extraAnswer)
  S->>ER: findByIdAndDeletedAtIsNull(eventId)
  alt event.ticketTypesが空でない
    S->>TR: findByIdAndEvent_Id(ticketTypeId, eventId)
    alt 区分が見つからない
      S-->>C: NotFoundException
      C-->>FE: 404「指定された区分が見つかりません」
    else 区分が見つかる
      S->>AR: countByTicketType_IdAndStatus(ticketTypeId, "受付済")
      Note over S: 以降は区分のcapacityと比較（既存の申込フローと同じ分岐）
    end
  else 区分なしイベント
    Note over S: v1.0までと同じ、イベント単位でevents.capacityと比較
  end
  S->>AR: save(new Application(user, event, ticketType, status, extraAnswer))
  S-->>C: ApplicationResponse
  C-->>FE: 201 Created
```

### 4.2 キャンセル待ちの順位表示（マイページ、機能追加）

```mermaid
sequenceDiagram
  participant FE as my-applications.ts
  participant C as ApplicationController
  participant S as ApplicationService
  participant AR as ApplicationRepository
  FE->>C: GET /api/my/applications
  C->>S: myApplications(userId)
  S->>AR: findByUser_IdOrderByAppliedAtDesc(userId)
  loop 各申込について
    alt statusが「キャンセル待ち」
      S->>AR: countByEvent_IdAndStatusAndAppliedAtLessThan(eventId, "キャンセル待ち", appliedAt)
      S->>S: waitlistRank = 件数 + 1
    else それ以外
      S->>S: waitlistRank = null
    end
  end
  S-->>C: MyApplicationResponse[]（waitlistRank付き）
  C-->>FE: 200 OK
```

### 4.3 お気に入り登録・解除（機能追加、冪等）

```mermaid
sequenceDiagram
  actor U as 一般ユーザー
  participant FE as event-list.ts / event-detail.ts
  participant C as FavoriteController
  participant S as FavoriteService
  participant FR as FavoriteRepository
  U->>FE: 「お気に入り」ボタン
  FE->>C: POST /api/favorites { eventId }
  C->>S: add(userId, eventId)
  S->>FR: findByUser_IdAndEvent_Id(userId, eventId)
  alt 既に登録済み
    S-->>C: 既存のFavoriteをそのまま返す
    C-->>FE: 200 OK（冪等）
  else 未登録
    S->>FR: save(new Favorite(user, event))
    S-->>C: 新規Favorite
    C-->>FE: 201 Created
  end
  U->>FE: もう一度押す（解除）
  FE->>C: DELETE /api/favorites/{eventId}
  C->>S: remove(userId, eventId)
  S->>FR: deleteByUser_IdAndEvent_Id(userId, eventId)
  S-->>C: （存在しなくてもエラーにしない）
  C-->>FE: 204 No Content
```

### 4.4 コメント投稿・削除（機能追加）

```mermaid
sequenceDiagram
  actor U as 利用者（一般・管理者とも）
  participant FE as event-detail.ts
  participant C as CommentController
  participant S as EventCommentService
  participant ER as EventRepository
  participant CR as EventCommentRepository
  U->>FE: コメントを入力して投稿
  FE->>C: POST /api/events/{id}/comments { body }
  C->>S: post(userId, eventId, body)
  S->>ER: findByIdAndDeletedAtIsNull(eventId)
  alt イベントが存在しない
    S-->>C: NotFoundException
    C-->>FE: 404
  else 存在する
    S->>CR: save(new EventComment(event, user, body))
    S-->>C: EventCommentResponse
    C-->>FE: 201 Created
  end
  U->>FE: 自分のコメントを「削除」
  FE->>C: DELETE /api/comments/{id}
  C->>S: delete(userId, commentId, isAdmin)
  S->>CR: findById(commentId)
  alt 投稿者本人でも管理者でもない
    S-->>C: ForbiddenException
    C-->>FE: 403「削除できません」
  else 本人または管理者
    S->>CR: delete(comment)
    S-->>C: 204
    C-->>FE: 204 No Content
  end
```

### 4.5 当日受付（チェックイン、機能追加）

```mermaid
sequenceDiagram
  actor A as 管理者
  participant FE as admin-checkin.ts（新規）
  participant EC as EventController
  participant AC as ApplicationController
  participant S as ApplicationService
  participant AR as ApplicationRepository
  A->>FE: イベント管理から「受付」を開く
  FE->>EC: GET /api/events/{id}/attendees
  EC->>S: listAttendees(eventId)
  S->>AR: findByEvent_IdOrderByAppliedAtAsc(eventId)
  S-->>EC: AttendeeResponse[]
  EC-->>FE: 200 OK（申込者一覧を表示）
  A->>FE: 来場者を選び「チェックイン」
  FE->>AC: PUT /api/applications/{id}/check-in
  AC->>S: checkIn(applicationId)
  S->>AR: findById(applicationId)
  alt statusが「受付済」以外
    S-->>AC: BusinessException
    AC-->>FE: 400「受付済の申込のみチェックインできます」
  else 「受付済」
    S->>S: application.checkIn() → checkedInAtに現在時刻
    S-->>AC: 200 OK
    AC-->>FE: 一覧を再表示（チェックイン済みが分かる表示に更新）
  end
```

## 5. バリデーション設計（追加分）

| 対象DTO | 制約 |
|---|---|
| `EventUpsertRequest`（拡張） | `organizerName`0〜100文字／`imageUrl`0〜500文字／`category`0〜50文字／`extraQuestion`0〜200文字／`ticketTypes`各要素の`name`必須・1〜50文字、`capacity`必須・1以上 |
| `ApplicationCreateRequest`（拡張） | `extraAnswer`0〜500文字。`ticketTypeId`は必須チェックをBean Validationではなく**Service層で条件付き判定**する（イベントによって必須可否が変わるため、静的なアノテーションでは表現できない） |
| `EventCommentCreateRequest`（新規） | `body`必須・1〜500文字 |

## 6. 例外設計（追加分）

新しい例外クラスは追加しない。既存4種類（`UnauthorizedException`/`ForbiddenException`/`NotFoundException`/`BusinessException`）の範囲で対応できる。

| 異常系 | 使う例外 | HTTPステータス |
|---|---|---|
| E8 チェックイン不可（受付済以外） | `BusinessException` | 400 |
| E9 お気に入り重複 | （例外を投げない。冪等に成功として処理） | 200／201／204 |
| E10 コメント削除の権限なし | `ForbiddenException` | 403 |
| E11 区分が見つからない | `NotFoundException` | 404 |
