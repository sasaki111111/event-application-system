## §0 共通事項（v1.1に追加）

v1.1の§0（ベースURL・認証方式・エラー形式・HTTPステータス方針・ページング無し・ソート方針等）はすべてそのまま適用する。以下を追加する。

| 項目 | 内容 |
|---|---|
| 冪等な操作の扱い | お気に入りの登録・解除（API-15・16）は、対象の状態がすでに希望通りである場合もエラーにせず成功として扱う（お気に入り登録済みへの再登録＝200、未登録への解除＝204）。トグル操作の連打で不要なエラーを出さないための方針 |
| 区分（`ticketTypeId`）の扱い | イベントに`ticketTypes`が1件以上ある場合は申込時に必須、無い場合は無視される（省略してよい）。詳細はAPI-03参照 |

## §2 既存APIの変更点（API-01〜14）

### API-01　GET `/api/events` — イベント一覧取得（フィールド追加）

レスポンスの各要素に以下を追加する（すべてNULL許容）。

| 名前 | 型 | 説明 |
|---|---|---|
| `organizerName` | string \| null | 主催者名 |
| `imageUrl` | string \| null | イベント画像URL |
| `category` | string \| null | カテゴリ |

他の項目・エラー・権限は v1.1 のまま。

### API-02　GET `/api/events/{id}` — イベント詳細取得（フィールド追加）

API-01の追加分に加えて、以下を追加する。

| 名前 | 型 | 説明 |
|---|---|---|
| `extraQuestion` | string \| null | 申込時アンケートの質問文言（NULL＝アンケート無し） |
| `ticketTypes` | TicketType[] | 区分一覧（0件＝区分なしイベント）。各要素：`id`, `name`, `capacity`, `acceptedCount`, `remaining` |
| `commentCount` | number | コメント数（一覧表示の目安。詳細本文はAPI-20で取得） |

**備考**：SC-04編集フォームの初期値表示にも本APIを流用する方針（v1.1と同じ）。`ticketTypes`もそのままフォームの初期値として使う。

### API-03　POST `/api/applications` — イベント申込（フィールド追加）

**リクエスト追加**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| body | `ticketTypeId` | number \| null | 条件付き必須 | 対象イベントに区分が1件以上ある場合は必須。無い場合は無視される |
| body | `extraAnswer` | string | 任意 | 対象イベントに`extraQuestion`がある場合のみ意味を持つ。0〜500文字 |

**レスポンス追加**：`ticketTypeId`（number \| null）

**エラー追加**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 400 | 区分があるイベントで`ticketTypeId`が未指定 | 区分を選択してください |
| 404 | 指定した`ticketTypeId`が対象イベントの区分として存在しない | 指定された区分が見つかりません（要件定義書E11） |

**定員判定の変更**：区分があるイベントでは「受付済数（同一`ticketTypeId`）＜ 区分の`capacity`」で判定する。区分が無いイベントはv1.1と同じ（イベント単位で`events.capacity`と比較）。

### API-04　GET `/api/my/applications` — 自分の申込一覧取得（フィールド追加）

レスポンスの各要素に以下を追加する。

| 名前 | 型 | 説明 |
|---|---|---|
| `waitlistRank` | number \| null | キャンセル待ちの順位（1始まり）。`status`が「キャンセル待ち」以外の場合はNULL |

### API-06／API-07　イベント登録・編集（フィールド追加）

**リクエスト追加**（すべて任意項目）

| 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|
| `organizerName` | string | 任意 | 0〜100文字 |
| `imageUrl` | string | 任意 | 0〜500文字 |
| `category` | string | 任意 | 0〜50文字 |
| `extraQuestion` | string | 任意 | 0〜200文字 |
| `ticketTypes` | {name: string, capacity: number}[] | 任意 | 0件＝区分なし。各要素の`name`は1〜50文字必須、`capacity`は1以上必須 |

**挙動**：`ticketTypes`を指定して保存すると、既存の区分は全置き換え（削除→再作成）する。**注意**：区分に紐づく申込（`applications.ticket_type_id`）が既にある状態での区分の削除・定員変更は、詳細設計フェーズで挙動を確定する（本書時点では「新規作成時のみ区分を追加できる」を暫定方針とし、既存区分がある申込済みイベントの区分編集はAPI-07では不可としてもよい）。

**備考**：`ticketTypes`を1件以上指定した場合、`events.capacity`はアプリ側で「区分の`capacity`合計」に自動設定する（テーブル定義書_v2.0.md§2.2参照）。

## §3 新規API詳細（API-15〜22）

### API-15　POST `/api/favorites` — お気に入り登録

**権限**：一般以上

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明 |
|---|---|---|---|---|
| body | `eventId` | number | 必須 | 対象イベントID |

**レスポンス**：201 Created（新規登録）／200 OK（既に登録済みだった場合、冪等）。body：`{ id, eventId, createdAt }`

**エラー**：404（イベントが存在しない）

**対応**：機能15／呼出画面：SC-02（一覧・詳細のお気に入りボタン）

---

### API-16　DELETE `/api/favorites/{eventId}` — お気に入り解除

**権限**：一般以上（本人のもののみ対象）

**リクエスト**：pathの`eventId`＝対象イベントID（`favorites.id`ではなくイベントIDで指定。ボタン側がイベントIDしか持たないため）

**レスポンス**：204 No Content（未登録だった場合も204、冪等）

**対応**：機能15／呼出画面：SC-02・SC-03

---

### API-17　GET `/api/my/favorites` — 自分のお気に入り一覧取得

**権限**：一般以上（本人分のみ）

**レスポンス**：200 OK ／ API-01と同じ形の配列＋`favoritedAt`（お気に入り登録日時）

**対応**：機能15／呼出画面：SC-03 マイページ（お気に入りタブ）

---

### API-18　GET `/api/events/{id}/attendees` — 申込者一覧取得（受付用）

**権限**：管理者のみ

**レスポンス**：200 OK ／ 下記フィールドの配列（申込日時昇順）

| 名前 | 型 | 説明 |
|---|---|---|
| `applicationId` | number | 申込ID |
| `userName` | string | 申込者名 |
| `ticketTypeName` | string \| null | 区分名（区分なしイベントはNULL） |
| `status` | string | 受付済／キャンセル待ち／キャンセル済 |
| `checkedInAt` | string \| null | チェックイン日時（未チェックインはNULL） |

**エラー**：403（一般ユーザー）、404（イベントが存在しない）

**対応**：機能19／呼出画面：SC-06（新規、受付画面）

---

### API-19　PUT `/api/applications/{id}/check-in` — チェックイン

**権限**：管理者のみ

**リクエスト**：pathの`id`＝申込ID。ボディなし

**レスポンス**：200 OK ／ `{ applicationId, checkedInAt }`

**エラー**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 400 | 対象申込のstatusが「受付済」以外 | 受付済の申込のみチェックインできます（要件定義書E8） |
| 403 | 一般ユーザーが実行 | 権限がありません |
| 404 | 指定IDの申込が存在しない | 申込が見つかりません |

**対応**：機能19／業務ロジック：チェックイン可否チェック／呼出画面：SC-06

---

### API-20　GET `/api/events/{id}/comments` — コメント一覧取得

**権限**：一般以上

**レスポンス**：200 OK ／ 下記フィールドの配列（投稿日時の昇順）

| 名前 | 型 | 説明 |
|---|---|---|
| `id` | number | コメントID |
| `userName` | string | 投稿者名 |
| `body` | string | 本文 |
| `createdAt` | string | 投稿日時（ISO8601） |
| `mine` | boolean | ログイン中のユーザー自身の投稿か（削除ボタンの表示判定用） |

**エラー**：404（イベントが存在しない）

**対応**：機能20／呼出画面：SC-02 イベント詳細

---

### API-21　POST `/api/events/{id}/comments` — コメント投稿

**権限**：一般以上（管理者も投稿可）

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| body | `body` | string | 必須 | 1〜500文字 |

**レスポンス**：201 Created ／ API-20の1要素と同じ形

**エラー**：400（未入力・文字数超過）、404（イベントが存在しない）

**対応**：機能20／呼出画面：SC-02 イベント詳細

---

### API-22　DELETE `/api/comments/{id}` — コメント削除

**権限**：一般以上（投稿者本人または管理者のみ）

**レスポンス**：204 No Content

**エラー**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 403 | 投稿者本人でも管理者でもない | 削除できません（要件定義書E10） |
| 404 | 指定IDのコメントが存在しない | コメントが見つかりません |

**対応**：機能20／業務ロジック：コメント削除可否チェック
