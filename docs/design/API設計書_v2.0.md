## §0 共通事項（全APIに適用）

| 項目 | 内容 |
|---|---|
| ベースURL | `http://localhost:8080` |
| パスプレフィックス | `/api`（全エンドポイント共通） |
| Content-Type | `application/json`（CSV出力APIを除く） |
| 文字コード | UTF-8 |
| 日付・時刻形式 | ISO 8601（例: `2026-10-01T18:00:00`） |
| 認証方式 | ダミー認証。`POST /api/login`（メールアドレス指定）または `POST /api/users`（会員登録）で受け取った `userId` を、以降の全リクエストのHTTPヘッダ `X-User-Id` に付与する。サーバは `X-User-Id` から users を引き role を判定。ヘッダ無し／存在しないIDは 401。 |
| 認可 | 各APIの「権限」欄参照。「本人のみ」は対象データの `user_id` と `X-User-Id` が一致する場合のみ許可。 |
| 共通エラーレスポンス | `@ControllerAdvice` が返すJSON：`{ "timestamp": ISO8601, "status": 数値, "error": 文字列, "message": 文字列 }` |
| バリデーションエラー形式 | 入力チェック（Bean Validation）違反は 400。共通エラーに `errors` 配列を加える：<br>`{ "status":400, "error":"Bad Request", "message":"入力エラー", "errors":[ {"field":"capacity","message":"1以上で入力してください"}, ... ] }` |
| リクエスト形式エラー | リクエスト本文が不正なJSON／型不一致／必須ボディ欠落、パスパラメータが数値でない場合は 400（`message` にエラー内容）。 |
| HTTPステータス方針 | 取得=200 ／ 作成=201 ／ 更新=200 ／ 削除=204 ／ 入力・業務エラー=400 ／ 認証切れ=401 ／ 権限不足=403 ／ 不在=404 |
| 冪等な操作 | お気に入りの登録・解除（API-15・16）は、対象の状態がすでに希望通りである場合もエラーにせず成功として扱う（トグル連打で不要なエラーを出さないため） |
| 区分（`ticketTypeId`）の扱い | イベントに`ticketTypes`が1件以上ある場合は申込時に必須、無い場合は無視される |
| 同時実行 | 定員ぎりぎりの同時申込のレース制御は実装しない（要件定義書§2）。 |
| ログアウト | サーバ状態を持たないため専用API無し。フロント側で保持中の `userId` を破棄するのみ。 |
| 「受付済数」の集計 | `acceptedCount`・充足率などの「受付済数」は `status='受付済'` のみを数える（キャンセル済は除外）。区分があるイベントは区分ごとに集計する。 |
| ページング | 実装しない（対象件数が小さいため全件返却）。 |
| ソート | `GET /api/events` は開催日時の昇順で固定。`GET /api/reports/applications` は `sort` パラメータで制御。`GET /api/events/{id}/comments` は投稿日時の昇順。 |

## §2 API設計詳細

### API-01　GET `/api/events` — イベント一覧取得

**権限**：一般以上（ログイン必須）

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| query | `status` | string | 任意 | 既定 `all`（受付終了分を含む全件・開催日時昇順）／`open`=申込受付中のみ |

**レスポンス（正常）**：200 OK

| 名前 | 型 | 説明 |
|---|---|---|
| (配列) | Event[] | 下記フィールドの配列（開催日時の昇順） |
| `id` | number | イベントID |
| `name` | string | イベント名 |
| `startAt` | string | 開催日時（ISO8601） |
| `place` | string | 場所 |
| `capacity` | number | 定員 |
| `applicationDeadline` | string | 申込締切日時（ISO8601） |
| `acceptedCount` | number | 受付済（`status='受付済'`）の申込数 |
| `open` | boolean | 申込受付中か |
| `organizerName` | string \| null | 主催者名 |
| `imageUrl` | string \| null | イベント画像URL |

**エラー**：業務エラーなし（認証切れ 401・形式不正 400 は §0 共通）

**対応**：機能4 ／ 呼出画面: SC-02 イベント一覧、SC-04 管理一覧（同一APIを流用）

### API-03　POST `/api/applications` — イベント申込

**権限**：一般のみ（申込者＝X-User-Id。管理者は403）

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| body | `eventId` | number | 必須 | 申し込むイベントのID |
| body | `ticketTypeId` | number \| null | 条件付き必須 | 対象イベントに区分が1件以上ある場合は必須。無い場合は無視される |
| body | `extraAnswer` | string | 任意 | 対象イベントに`extraQuestion`がある場合のみ意味を持つ。0〜500文字 |

**レスポンス（正常）**：201 Created

| 名前 | 型 | 説明 |
|---|---|---|
| `id` | number | 申込ID |
| `eventId` | number | イベントID |
| `ticketTypeId` | number \| null | 申し込んだ区分 |
| `userId` | number | 申込者ID |
| `status` | string | 受付済（定員に空きがある場合）／キャンセル待ち（定員に達している場合） |
| `appliedAt` | string | 申込日時（ISO8601） |

**エラー**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 400 | 現在 > 申込締切 または 現在 ≧ 開催日時 | 申込受付は終了しました |
| 400 | 同一ユーザーが同一イベントに「受付済」または「キャンセル待ち」の申込を保持している | すでに申し込み済みです |
| 400 | 区分があるイベントで`ticketTypeId`が未指定 | 区分を選択してください（E12） |
| 403 | 管理者が実行 | 管理者は申込できません |
| 404 | eventId のイベントが存在しない | イベントが見つかりません |
| 404 | 指定した`ticketTypeId`が対象イベントの区分として存在しない | 指定された区分が見つかりません（E11） |

**対応**：機能8 ／ 業務ロジック: 定員超過時の登録・申込締切/日付チェック・二重申込チェック・区分存在/必須チェック・権限チェック（一般限定） ／ 呼出画面: SC-02

**備考**：申込完了画面（SC-02 `/events/:id/done`）は本APIのレスポンスをそのまま表示する。専用API無し・画面リロード非対応。定員超過時も400エラーにはせず、201でキャンセル待ち登録として成功させる。定員判定は、区分があるイベントでは区分単位（`ticketTypeId`ごとの受付済数と区分の`capacity`）、無い場合はイベント単位で行う。

### API-05　DELETE `/api/applications/{id}` — 申込キャンセル

**権限**：一般以上（対象申込の `user_id` ＝ `X-User-Id` のときのみ）

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| path | `id` | number | 必須 | 申込ID |

**レスポンス（正常）**：204 No Content（`status` を「キャンセル済」に更新）／レスポンスボディなし

**エラー**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 400 | 対象申込が「キャンセル済」、または対象イベントの開催日時を経過 | 取消できません |
| 403 | 対象申込が他ユーザーのもの | 権限がありません |
| 404 | 指定IDの申込が存在しない | 申込が見つかりません |

**対応**：機能10 ／ 業務ロジック: 取消可否チェック・キャンセル待ちの繰り上げ ／ 呼出画面: SC-03 マイページ

**備考**：対象が「受付済」または「キャンセル待ち」であれば取消可能。「受付済」の申込を取消した場合、同一イベント（区分がある場合は同一区分）で最も申込日時が古い「キャンセル待ち」の申込があれば自動的に「受付済」へ繰り上げる。

### API-06　POST `/api/events` — イベント登録

**権限**：管理者のみ

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約（バリデーション） |
|---|---|---|---|---|
| body | `name` | string | 必須 | 1〜100文字 |
| body | `startAt` | string | 必須 | 未来日時。ISO8601 |
| body | `place` | string | 必須 | 1〜100文字 |
| body | `capacity` | number | 必須 | 1以上 |
| body | `applicationDeadline` | string | 必須 | `startAt` 以前の日時。ISO8601 |
| body | `description` | string | 任意 | 0〜1000文字 |
| body | `organizerName` | string | 任意 | 0〜100文字 |
| body | `imageUrl` | string | 任意 | 0〜500文字 |
| body | `extraQuestion` | string | 任意 | 0〜200文字 |
| body | `ticketTypes` | {name, capacity}[] | 任意 | 0件＝区分なし。各要素の`name`は1〜50文字必須、`capacity`は1以上必須 |

**レスポンス（正常）**：201 Created ／ body = Event（API-02 と同じ形）

**エラー**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 400 | 必須未入力／文字数超過／capacity<1／applicationDeadline が startAt より後／startAt が過去／区分の`name`未入力・`capacity`<1 | 入力エラー（詳細は `errors` 配列。§0参照） |
| 403 | 一般ユーザーが実行 | 権限がありません |

**対応**：機能11 ／ 呼出画面: SC-04 イベント登録・編集フォーム

**備考**：`ticketTypes`を1件以上指定した場合、`events.capacity`は区分の`capacity`合計をアプリ側で自動設定する。

### API-07　PUT `/api/events/{id}` — イベント編集

**権限**：管理者のみ

**リクエスト**：API-06と同じ項目（path`id`が追加）

**レスポンス（正常）**：200 OK ／ body = Event（API-02 と同じ形）

**エラー**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 400 | API-06と同じ入力バリデーション違反 | 入力エラー（詳細は`errors`配列。§0参照） |
| 400 | `ticketTypes`を指定していて、対象イベントの区分に「受付済」または「キャンセル待ち」の申込が1件以上ある | 区分に申込があるため変更できません |
| 400 | `ticketTypes`を指定していて、区分を削除する際にキャンセル済の申込の履歴が区分を参照したまま残っている | 区分に申込の履歴が残っているため変更できません |
| 404 | 指定IDのイベントが存在しない | イベントが見つかりません |

**対応**：機能12 ／ 業務ロジック: 区分変更時の申込チェック ／ 呼出画面: SC-04 イベント登録・編集フォーム

**備考**：`ticketTypes`を指定して保存すると、既存の区分は全置換（削除→再作成）する。`ticketTypes`を指定しない場合は既存の区分に一切手を加えない（上記のチェックも行わない）。

### API-09　GET `/api/reports/applications` — 申込実績取得（JSON／CSV）

**権限**：管理者のみ

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| query | `format` | string | 任意 | 既定 `json`。`json`／`csv` |
| query | `sort` | string | 任意 | 既定 `startAt`。`startAt`=開催日時昇順／`accepted_desc`=受付済数の多い順 |

**レスポンス（正常, format=csv）**：200 OK

| 項目 | 仕様 |
|---|---|
| Content-Type | `text/csv; charset=UTF-8` |
| 文字コード | UTF-8（BOM付き）。Excelで開いた際の文字化けを防ぐため先頭にBOM（`EF BB BF`）を付与する |
| 区切り文字・改行 | カンマ区切り、改行はCRLF（Excel互換）。値にカンマ・改行・ダブルクォートを含む場合はRFC4180に従いダブルクォートで囲む |

| 出力単位 | 1行＝1申込（イベント単位の集計ではなく申込明細）。対象・並び順は要件定義書_v2.0.md §12を参照 |
| 列構成（1行目はヘッダー） | 1. イベント名　2. 開催日時（`yyyy-MM-dd HH:mm`）　3. 区分名（区分の無いイベントは空欄）　4. 申込者氏名　5. 申込者メールアドレス　6. ステータス　7. 申込日時（`yyyy-MM-dd HH:mm`）　8. チェックイン日時（未チェックインは空欄） |

**エラー**：403（一般ユーザーが実行）

**対応**：機能15 ／ 呼出画面: SC-05 申込状況・実績

### API-10　POST `/api/login` — ダミーログイン（メールアドレス指定）

### API-19　PUT `/api/applications/{id}/check-in` — チェックイン

**権限**：管理者のみ

**レスポンス**：200 OK ／ `{ applicationId, checkedInAt }`

**エラー**

| HTTPステータス | 発生条件 | message |
|---|---|---|
| 400 | 対象申込のstatusが「受付済」以外 | 受付済の申込のみチェックインできます（E8） |
| 403 | 一般ユーザーが実行 | 権限がありません |
| 404 | 指定IDの申込が存在しない | 申込が見つかりません |

**対応**：機能19／業務ロジック：チェックイン可否チェック／呼出画面：SC-06
