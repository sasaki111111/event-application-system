## §0 共通事項（全APIに適用）

| 項目 | 内容 |
|---|---|
| ベースURL | `http://localhost:8080` |
| パスプレフィックス | `/api`（全エンドポイント共通） |
| Content-Type | `application/json`（CSV出力APIを除く） |
| 文字コード | UTF-8 |
| 日付・時刻形式 | ISO 8601（例: `2026-10-01T18:00:00`） |
| 認証方式 | ダミー認証。`POST /api/login` で受け取った `userId` を、以降の全リクエストのHTTPヘッダ `X-User-Id` に付与する。サーバは `X-User-Id` から users を引き role を判定。ヘッダ無し／存在しないIDは 401。 |
| 認可 | 各APIの「権限」欄参照。「本人のみ」は対象データの `user_id` と `X-User-Id` が一致する場合のみ許可。 |
| 共通エラーレスポンス | `@ControllerAdvice` が返すJSON：`{ "timestamp": ISO8601, "status": 数値, "error": 文字列, "message": 文字列 }` |
| バリデーションエラー形式 | 入力チェック（Bean Validation）違反は 400。共通エラーに `errors` 配列を加える：<br>`{ "status":400, "error":"Bad Request", "message":"入力エラー", "errors":[ {"field":"capacity","message":"1以上で入力してください"}, ... ] }` |
| リクエスト形式エラー | リクエスト本文が不正なJSON／型不一致／必須ボディ欠落、パスパラメータが数値でない場合は 400（`message` にエラー内容）。 |
| HTTPステータス方針 | 取得=200 ／ 作成=201 ／ 更新=200 ／ 削除=204 ／ 入力・業務エラー=400 ／ 認証切れ=401 ／ 権限不足=403 ／ 不在=404 |
| 同時実行 | 要件定義§2 により、定員ぎりぎりの同時申込のレース制御は実装しない。 |
| ログアウト | サーバ状態を持たないため専用API無し。フロント側で保持中の `userId` を破棄するのみ。 |
| 「受付済数」の集計 | `acceptedCount`・充足率などの「受付済数」は `status='受付済'` のみを数える（キャンセル済は除外）。 |
| ページング | 実装しない（対象件数が小さいため全件返却）。 |
| ソート | `GET /api/events` は開催日時の昇順で固定。`GET /api/reports/applications` は `sort` パラメータで制御。 |

## §2 API設計書（各APIの詳細）

### API-01　GET `/api/events` — イベント一覧取得

**権限**：一般以上（ログイン必須）

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| query | `status` | string | 任意 | 既定 `all`（受付終了分を含む全件・開催日時昇順）／`open`=申込受付中のみ。SC-02・SC-04 とも既定(all)で取得し、`open=false` の行を「受付終了・申込ボタン非活性」で表示（要件定義§2） |

**レスポンス（正常）**：200 OK

| 名前 | 型 | 説明 |
|---|---|---|
| (配列) | Event[] | 下記フィールドの配列（開催日時の昇順） |
| `id` | number | イベントID |
| `name` | string | イベント名 |
| `startAt` | string | 開催日時（ISO8601） |
| `place` | string | 場所 |
| `capacity` | number | 定員 |
| `applicationDeadline` | string | 申込締切日時（ISO8601） |
| `acceptedCount` | number | 受付済（`status='受付済'`）の申込数 |
| `open` | boolean | 申込受付中か（現在≦締切 かつ 現在<開催日時） |

**エラー**：業務エラーなし（認証切れ 401・形式不正 400 は §0 共通）

**対応**：機能2 ／ 呼出画面: SC-02 イベント一覧、SC-04 管理一覧（同一APIを流用）

### API-03　POST `/api/applications` — イベント申込

**権限**：一般のみ（申込者＝X-User-Id。管理者は403）

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| body | `eventId` | number | 必須 | 申し込むイベントのID |

**レスポンス（正常）**：201 Created

| 名前 | 型 | 説明 |
|---|---|---|
| `id` | number | 申込ID |
| `eventId` | number | イベントID |
| `userId` | number | 申込者ID |
| `status` | string | 受付済（固定） |
| `appliedAt` | string | 申込日時（ISO8601） |

**エラー**

| HTTPステータス | 発生条件 | message（画面表示文言） |
|---|---|---|
| 400 | 受付済の申込数 ≧ 定員 | 定員に達しています |
| 400 | 現在 > 申込締切 または 現在 ≧ 開催日時 | 申込受付は終了しました |
| 400 | 同一ユーザーが同一イベントに「受付済」の申込を保持している | すでに申し込み済みです |
| 403 | 管理者が実行 | 管理者は申込できません |
| 404 | eventId のイベントが存在しない | イベントが見つかりません |

**対応**：機能4 ／ 業務ロジック: 定員超過チェック・申込締切/日付チェック・二重申込チェック・権限チェック（一般限定） ／ 呼出画面: SC-02

**備考**：申込完了画面（SC-02 `/events/:id/done`）は本APIのレスポンスをそのまま表示する。専用API無し・画面リロード非対応。

### API-06　POST `/api/events` — イベント登録

**権限**：管理者のみ

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約（バリデーション） |
|---|---|---|---|---|
| body | `name` | string | 必須 | 1〜100文字（`@NotBlank @Size(max=100)`） |
| body | `startAt` | string | 必須 | 未来日時（`@Future`）。ISO8601 |

| body | `applicationDeadline` | string | 必須 | `startAt` 以前の日時。ISO8601 |

**エラー**

| HTTPステータス | 発生条件 | message（画面表示文言） |
|---|---|---|
| 400 | 必須未入力／文字数超過／capacity<1／applicationDeadline が startAt より後／startAt が過去 | 入力エラー（詳細は `errors` 配列。§0参照） |
| 403 | 一般ユーザーが実行 | 権限がありません |

**対応**：機能7 ／ 呼出画面: SC-04 イベント登録・編集フォーム

### API-09　GET `/api/reports/applications` — 申込実績取得（JSON／CSV）

**権限**：管理者のみ

**リクエスト**

| 位置 | 名前 | 型 | 必須 | 説明・制約 |
|---|---|---|---|---|
| query | `format` | string | 任意 | 既定 `json`。`json`／`csv` |
| query | `sort` | string | 任意 | 既定 `startAt`。`startAt`=開催日時昇順／`accepted_desc`=受付済数の多い順 |

**レスポンス（正常）**：200 OK

`format=json:` 下記フィールドの配列

| 名前 | 型 | 説明 |
|---|---|---|
| `eventId` | number | イベントID |
| `eventName` | string | イベント名 |
| `startAt` | string | 開催日時（ISO8601） |
| `capacity` | number | 定員 |
| `acceptedCount` | number | 受付済（`status='受付済'`）の申込数 |
| `fillRate` | number | 充足率＝受付済数÷定員（小数2桁） |

`format=csv:` `Content-Type: text/csv; charset=UTF-8`、`Content-Disposition: attachment; filename=applications_report.csv`。ヘッダ行＋各申込明細（イベント名／申込者名／申込日時／ステータス）

**エラー**

| HTTPステータス | 発生条件 | message（画面表示文言） |
|---|---|---|
| 403 | 一般ユーザーが実行 | 権限がありません |

**対応**：機能10 ／ 呼出画面: SC-05 申込状況・実績

**備考**：`format=csv`（イベント名／申込者名／申込日時／ステータスの明細）が §4.2 型7 の必須部分。`format=json` のイベント別集計（受付済数・充足率）＋ `sort=accepted_desc`（人気度）は チーム独自機能（要件定義§2）。
