# 07-06 問題・確認事項

[07_システム動作・実装対応チェックリスト.md](07_システム動作・実装対応チェックリスト.md) の補助資料。本調査（設計書・コード読解、自動テスト実行、フロントエンド本番ビルド）で発見した事項を記録する。

分類の凡例：
- **A** 明らかな実装不備（設計は明確で、コード側が誤っている）
- **B** 設計と実装の不一致（どちらが正しいか要確認）
- **C** 設計の不足（設計書だけでは実装・動作を判断できない）
- **D** 未確認（コード上は問題なさそうだが、実動作を確認できていない）

本調査で発見した事項はいずれも **A（機能上の実装不備）には該当しなかった**。以下は軽微な記録事項（ドキュメント表記の不一致・未使用コード）と、実機確認の状況（D）の一覧である。No.1・No.2は対応方針が決まったため反映済み、No.3は実施予定として記録する。

## No.1　コード内コメントの旧API番号と現行API設計書の番号が対応していない

| 項目 | 内容 |
|---|---|
| 対象 | `EventController.java`, `ApplicationController.java`, `FavoriteController.java`ほか、backend各所のコメント（controller/service/repository/entity/dto、計約70箇所）、`ApiIntegrationTest.java`（テストメソッド名7件を含む）、`db/schema.sql`（2箇所） |
| 設計書 | `docs/03_API設計書.md`はAP-01〜AP-25の通番（例：AP-04=イベント一覧取得, AP-11=申込者一覧取得, AP-12=イベント申込） |
| 発見時の状態 | コード内コメントは開発初期（B〜D工程）に振られた別の通番「API-01」「API-03」等を使用しており、現行のAP-XXとは対応しない別の採番だった（例：`EventController.list()`のコメントは「API-01 GET /api/events」＝実際はAP-04に相当）。 |
| 対応 | ユーザー指示「現在のものに合わせてAP-××のようにすべて揃えてください」を受け、本セッションで全箇所を現行のAP-XX番号に統一した。あわせて`ApiIntegrationTest.java`の一部テストメソッド名（`api01_...`〜`api06_...`）も、既存の新しいテスト（`ap09_...`, `ap23_...`, `ap25_...`）と同じ命名規則（小文字`ap`＋現行番号）に統一した（`ap04_イベント一覧取得`, `ap05_イベント詳細取得`, `ap07_管理者はイベントを登録できる`/`ap07_一般ユーザーはイベントを登録できない`, `ap12_一般ユーザーは申込できる`, `ap13_自分の申込一覧取得`, `ap14_申込をキャンセルできる`）。修正後、`mvn test`で67件全て成功することを確認済み。[07-04_API確認表.md](07-04_API確認表.md)内の該当テスト名引用も合わせて更新した。 |
| ステータス | **解決済み** |

## No.2　`TicketTypeRepository.findByIdAndEvent_Id`（非ロック版）が未使用

| 項目 | 内容 |
|---|---|
| 対象 | `backend/src/main/java/com/example/eventapp/repository/TicketTypeRepository.java` |
| 発見時の状態 | ロック無し版`findByIdAndEvent_Id(id, eventId)`が宣言されていたが、呼び出し箇所が無かった（実際に使用されているのは悲観ロック版`findByIdAndEvent_IdForUpdate`のみ）。 |
| 対応 | ユーザー確認「削除しても問題ありません」を受け、本セッションで削除した。削除後、`mvn test`で67件全て成功することを確認済み（挙動への影響なし）。 |
| ステータス | **解決済み（削除完了）** |

## No.3　追加機能の実ブラウザ操作による動作確認

| 項目 | 内容 |
|---|---|
| 対象 | お気に入り・イベントコメント・参加区分（定員区分）・当日受付・イベント検索・カレンダー表示・削除済みイベントの復元・管理者アカウント登録・管理者ダッシュボードなど、`docs/F-1_結合動作確認記録.md`／`docs/F-2_業務シナリオ実行結果.md`／`docs/D-8_API疎通確認記録.md`（いずれも2026-09-14〜15実施）より後に追加された機能群 |
| 発見時の状態 | コード読解と自動テスト（H2使用、67件成功）でのみ設計どおりであることを確認済みで、実MySQL環境での確認は未実施だった（環境上の制約：MySQL未起動、ブラウザ操作ツール無し）。 |
| 対応 | ユーザーが実MySQLを起動したため、本セッション内で`mvnw spring-boot:run -Dspring-boot.run.profiles=local`によりbackendを実MySQL（`eventapp`DB）に接続して起動し、curlによるAPI疎通確認（D-8と同じ手法）を実施した。以下の16 API（前回未確認だったAP-06/10/11/15を含む）について、実際にMySQLへ読み書きされることを確認：AP-05〜AP-21のうち検証範囲（区分あり申込・区分単位のキャンセル待ち・繰り上げ・当日受付一覧・チェックイン／再チェックイン・お気に入り登録/解除/一覧（冪等性含む）・コメント投稿/一覧/mine判定/削除権限・イベント削除/削除済み一覧/復元）。検証用に作成した一時イベント（`動作確認用イベント(自動テスト)`、区分「一般枠」「優先枠」）とその申込・お気に入り・コメントは、確認後すべてキャンセル／削除／解除のうえイベント自体もソフトデリートして後始末済み。既存データ（ユーザー5件、イベント既存分、旧テスト分）への影響は無い。あわせてDB内を確認したところ、`CSV除外確認用イベント`・`チェックイン確認用イベント`・`UI再チェックイン確認用`という名称の削除済みテストイベントが本セッション開始前（同日11:32〜11:40）から既に存在しており、CSV除外・チェックイン・再チェックイン確認ダイアログについても過去に動作確認が行われていたことを示す記録が見つかった。また管理者アカウントが seed の2件に加えて3件存在し（`newadmin2@example.com`等）、AP-25管理者アカウント登録についても実運用で使用された形跡があった。 |
| 未確認として残る範囲 | 上記はいずれもAPI・DB層の実データでの確認であり、Angular画面を実際にブラウザで操作しての確認（ボタンクリック・カレンダー表示・確認ダイアログの見た目等）は、本セッションにはブラウザ操作ツールが無いため引き続き未実施。 |
| ステータス | **一部対応済み（API・実DB層は実機確認完了）**。画面操作（ブラウザ）による最終確認は利用者側で実施予定。 |
