# 43_総合テスト仕様書

## 1. 概要

本書は、総合テスト（ST）のテストケースを定める。テストレベルの定義、テストケースの書き方、テストIDの体系、テストデータ（TD-00〜TD-05）、合否の基準、証跡は`docs/40_テスト/40_テスト計画書.md`に定める。

総合テストは、結合テスト（`docs/40_テスト/42_結合テスト仕様書.md`）で機能ごとに確認した内容を前提に、次の2点を確認する。

| 種類 | 確認すること | 根拠 |
|---|---|---|
| 業務シナリオ（2章・3章） | 業務の流れに沿って、複数の機能・複数の利用者をまたいで操作したときに、画面とデータが一貫していること | `docs/10_要件定義/10_要件定義書.md`4章（業務フロー）・7章（業務ルール） |
| 非機能（4章） | 排他制御、回数制限、セキュリティ、障害時の表示、ログが、定めた方式のとおりであること | `docs/10_要件定義/10_要件定義書.md`10章、`docs/20_基本設計/24_方式設計書.md` |

- 業務シナリオは、業務が最後まで進む「正常系シナリオ」と、業務ルールによって操作が拒否される「異常系シナリオ」に分ける。
- シナリオの各ステップは、前のステップの結果を前提とする。途中で不合格になった場合はそのステップで中断し、不具合を起票する。
- 各シナリオは、`schema.sql`→`seed.sql`を投入し、テスト計画書6章のTD-01〜TD-05を用意した状態から開始する。シナリオごとに状態を作り直す。
- 「操作する人」の利用者は次のとおり。複数の利用者が登場するシナリオでは、利用者ごとに別のブラウザ（または別のシークレットウィンドウ）を使う。

| 表記 | 利用者 |
|---|---|
| 一般A | 一般ユーザー（`general@example.com`） |
| 一般B | 一般ユーザー2（`general2@example.com`、TD-05） |
| 一般C | シナリオの中で新規登録する利用者 |
| 管理者 | 管理者（`admin@example.com`） |
