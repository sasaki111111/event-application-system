# 41_単体テスト仕様書

## 1. 概要

本書は、単体テスト（UT）のテストケースを定める。テストレベルの定義、テストケースの書き方、テストIDの体系、合否の基準、証跡は`docs/40_テスト/40_テスト計画書.md`に定める。

- 単体テストはすべて自動テストである。バックエンドは`backend`で`mvnw test`、フロントエンドは`frontend`で`npm test`を実行する。
- バックエンドの単体テストは、Service層の業務ロジックを対象とし、Repository（データベースへのアクセス）を模擬のものに置き換えて実行する。データベースの更新結果の確認は結合テスト（`docs/40_テスト/42_結合テスト仕様書.md`）で行う。
- テストケースと自動テストは1対1で対応する。「自動テスト」列は、そのテストケースを確認するテストメソッドの名前を示す。
- 「根拠」列の`R-xx`は`docs/30_詳細設計/32_処理詳細設計書.md`5章の業務ルール、`C-xx`は`docs/30_詳細設計/33_共通詳細設計書.md`2.2のチェック、`E-x-xxx`は同3章のエラー、`AP-xxx`は`docs/30_詳細設計/31_API詳細設計書.md`のAPIを指す。
