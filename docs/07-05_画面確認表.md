# 07-05 画面確認表

[07_システム動作・実装対応チェックリスト.md](07_システム動作・実装対応チェックリスト.md) の補助資料。`docs/04_画面設計書.md`のSC-01〜SC-14について、設計内容と実装（Component／HTML／API呼び出し／バリデーション／遷移）の対応を確認する。

各画面は `frontend/src/app/**/*.ts` + 対応する `*.html` の2ファイル構成（+ `*.css`）。ルーティングは `app.routes.ts` に集約され、保護は `authGuard`（未ログイン→`/login`）・`adminGuard`（管理者以外→`/events`）で行う。

---

## SC-01 ログイン `/login`

- **目的**：メールアドレスによるログイン、または名前・メールアドレスによる新規登録。
- **Component**：`login/login.ts`（`Login`）／`login/login.html`
- **API**：AP-01（`LoginApiService.login`）、AP-02（`LoginApiService.register`）
- **入力**：ログイン用メールアドレス、登録用の名前・メールアドレス（signalで個別管理）
- **バリデーション**：ログインは空欄なら`errorMessage`をセットしAPI未呼び出し（`login()`冒頭の`if(!email)`）。登録側はクライアント側必須チェックを行わずAPI（サーバー側`@NotBlank`等）の結果に従う（設計書どおり「それ以外の項目はAPIから返される検証結果に従う」）。
- **エラー表示**：401→固定文言、400＋`errors`→登録フィールドごとに`registerFieldError(field)`で表示。
- **遷移**：ログイン/登録成功で`role`に応じ`/admin/dashboard`または`/events`へ。ルーティング：`{ path: 'login', component: Login }`（ガード無し、`app.routes.ts:26`）。
- **ルーティング確認**：認証保護対象外の唯一の画面。
- **結果**：✓ 確認済み

## SC-02 イベント一覧 `/events`

- **目的**：イベント一覧表示（一覧／カレンダー切替）とその場での申込・お気に入り。
- **Component**：`events/event-list/event-list.ts`（`EventList`）／`.html`
- **API**：AP-04（一覧）、AP-05（行展開時の詳細）、AP-12（申込）、AP-16/17（お気に入り、`FavoriteStore`経由）、AP-18（`FavoriteStore.ensureLoaded()`）
- **表示**：`viewMode` signal（`'list'|'calendar'`）で一覧/カレンダーを切替。カレンダーは`calendarWeeks` computedが42マス（6週）を生成し当日・月外日をマーキング。
- **入力**：展開時の`selectedTicketTypeId`・`extraAnswer`。
- **バリデーション**：区分必須違反はサーバー応答（400）に従う（設計書どおり）。
- **管理者制御**：`isAdmin`（`DummyUserStore.isAdmin()`、role基準＝D-03）が真の間は申込フォームを表示しない（要件定義書E7）。
- **遷移**：申込成功→`router.navigate(['/events', eventId, 'done'], {state:{application}})`（SC-05）。
- **ルーティング**：`{ path: 'events', component: EventList, canActivate: [authGuard] }`
- **結果**：△ 実機未確認（カレンダー表示・展開申込はコード読解で確認、F-1記録はカレンダー機能追加前のため未カバー）

## SC-04 イベント詳細・申込 `/events/:id`

- **目的**：詳細確認・申込・お気に入り・コメント。
- **Component**：`events/event-detail/event-detail.ts`（`EventDetail`）
- **API**：AP-05（詳細）、AP-12（申込）、AP-16/17（お気に入り）、AP-19/20/21（コメント一覧/投稿/削除）
- **「戻る」導線**：`ngOnInit`で`queryParamMap.get('from')==='search'`なら`backLink='/events/search'`、それ以外は既定`/events`（設計書§5の分岐と一致）。
- **バリデーション**：コメント本文が空の場合`postComment()`が早期returnしAPIを呼ばない（設計書「投稿ボタンを押下できない」相当をロジック側で実現。ボタン自体の`disabled`制御は`.html`側、後述）。
- **エラー表示**：詳細取得失敗→画面全体にエラー（`errorMessage`）。コメント取得失敗はイベント詳細表示をブロックしない（`loadComments()`のerrorハンドラが空実装）。
- **遷移**：申込成功→SC-05へnavigation state付き遷移。
- **ルーティング**：`{ path: 'events/:id', component: EventDetail, canActivate: [authGuard] }`
- **結果**：△ 実機未確認（お気に入り・コメント機能はF-1記録の対象外〔追加前〕）

## SC-09 イベント登録・編集 `/admin/events/new` , `/admin/events/:id/edit`

- **目的**：イベント・参加区分の新規登録／編集（同一コンポーネント）。
- **Component**：`admin/admin-event-form/admin-event-form.ts`（`AdminEventForm`）

- **入力**：Reactive Forms（`FormBuilder.nonNullable.group`）。`ticketTypes`は`FormArray`で行の追加・削除（`addTicketType()`/`removeTicketType()`）。

- **遷移**：保存成功→`/admin/events`（SC-08）。
- **モード判定**：`route.snapshot.paramMap.get('id')`の有無で新規/編集を分岐（`isEditMode` getter）。
- **ルーティング**：`{ path: 'admin/events/new', ... }` / `{ path: 'admin/events/:id/edit', ... }`（いずれも`authGuard, adminGuard`）
