# 33_共通詳細設計書

## 1. 概要

本書は、`docs/20_基本設計/24_方式設計書.md`に定めた方式（入力チェック、エラー処理、認証・認可、ログ）について、個々のチェック・エラー・ログ出力の一覧と実装方法を定義する詳細設計書である。他の設計書が参照するエラーID（`E-V-`・`E-B-`・`E-A-`・`E-R-`・`E-S-`）は、すべて本書3章に定める。

## 2. 入力チェック

### 2.1 実装方法

| チェックの種類 | 実装方法 | 違反時 |
|---|---|---|
| 単項目チェック（必須、桁数、形式） | リクエストを受け取るクラス（DTO）の各項目にBean Validationのアノテーションを付与する | 違反した項目を全てまとめて400で返す（`errors[]`に項目名とメッセージ） |
| 項目間のチェック（DTO内で完結するもの） | DTOに独自のアノテーションを付与する（`@ValidEventDates`） | 単項目チェックと同時に判定し、同じ形式で返す |
| データベースとの照合、業務ルール | Service層で判定する | 最初に見つかった1件を例外として返す |

**認可を先に行うAPIでの実装**：管理者専用のAPI（イベント登録・更新、管理者アカウント登録）および一般利用者専用のAPI（イベント申込）では、Springの自動検証（`@Valid`）を使わず、Controllerの中で認可チェックを行った後に検証（`Validator#validate`）を呼び出す。これにより、権限のない利用者には入力エラー（400）ではなく権限エラー（403）を返す。それ以外のAPIは`@Valid`を使用する。

**使用するアノテーション**

| アノテーション | チェック内容 |
|---|---|
| `@NotNull` | 未指定を認めない |
| `@NotBlank` | 未指定・空文字・空白のみを認めない（文字列） |
| `@Size(min=, max=)` | 文字数の下限・上限 |
| `@Min(value=)` | 数値の最小値 |
| `@Email` | メールアドレスの形式 |
| `@Future` | 現在より未来の日時 |
| `@Pattern(regexp=)` | 正規表現による形式。共通の正規表現は`ValidationPatterns`に定義し、複数のDTOで共用する |
| `@Valid`（項目に付与） | 入れ子の要素（`ticketTypes`の各要素）にも検証を適用する |

**共通の正規表現（`ValidationPatterns`）**

| 名称 | 内容 | 適用する項目 |
|---|---|---|
| `NO_CONTROL_CHARS` | 制御文字（タブ・改行・復帰を除く）、ゼロ幅文字、BOMを含まないこと | 名前、イベント名、場所、説明、主催者名、アンケート文言、参加区分名、アンケート回答、コメント本文 |
| `HTTP_URL` | `http://`または`https://`で始まること | 画像URL |
| `PASSWORD` | 半角の英字・数字・記号のみで構成され、英字と数字をそれぞれ1文字以上含むこと | パスワード（利用者登録、管理者アカウント登録、パスワード変更の新しいパスワード） |

**メールアドレスの正規化**：ログイン・利用者登録・管理者アカウント登録では、リクエストをDTOに変換する時点で前後の空白を除去し、形式チェックは除去後の値に対して行う。小文字化は`UserService#normalizeEmail`で行い、照合・重複チェック・保存には正規化後の値を用いる。

## 4. 例外とHTTPステータスの変換

`GlobalExceptionHandler`（`@RestControllerAdvice`）が、全てのControllerで発生した例外をまとめてエラーレスポンス（`docs/20_基本設計/23_API基本設計書.md`2.3）へ変換する。各Controllerには個別の例外処理を書かない。

| 例外クラス | 発生させる場所 | HTTP | 備考 |
|---|---|---|---|
| `UnauthorizedException` | `AuthInterceptor`（未ログイン）、`UserService#login`（該当する利用者が無い、退会済み、パスワードの不一致） | 401 | |
| `ForbiddenException` | `AuthContext#requireAdmin`、`ApplicationController#requireGeneral`、`ApplicationService#cancel`（本人以外）、`EventCommentService#delete`（権限なし） | 403 | |
| `NotFoundException` | 各Serviceの`orElseThrow`（イベント・申込・区分・コメント・利用者が対象） | 404 | |
| `BusinessException` | 各Serviceの業務ルール違反判定 | 400 | |
| `MethodArgumentNotValidException` | Spring（`@Valid`違反時に自動発生） | 400 | `errors`に項目ごとのエラーを詰める |
| `ConstraintViolationException` | Spring（Controller内で手動`validate()`を呼ぶ場合の`@Valid`相当） | 400 | 同上 |
| `HttpMessageNotReadableException` | Spring（不正なJSON等） | 400 | リクエスト形式エラー |
| `MethodArgumentTypeMismatchException` | Spring（パスパラメータの型不一致等） | 400 | リクエスト形式エラー |
| `Exception`（上記以外すべて） | `GlobalExceptionHandler#handleUnexpected` | 500 | E-S-001として処理する。スタックトレースはログにのみ出す（6.2）。画面には内部情報を出さない（`application.yml`の`server.error.include-stacktrace: never`も参照） |

想定外の例外では、スタックトレースをログにのみ出力し、レスポンスには固定のメッセージだけを返す。Springが既定で返すエラー応答からも内部情報が漏れないよう、設定ファイルで`server.error.include-stacktrace: never`を指定する。

## 5. 認証・認可の実装

### 5.1 処理の流れ

| 場面 | 画面側（Angular） | サーバー側（Spring Boot） |
|---|---|---|
| ログイン | SC-010からAP-010を呼び出し、応答の利用者ID・利用者区分（コード）を`LoginUserStore`に保持する。`localStorage`にも保存し、再読み込み後もログイン状態を維持する | `UserService#login`がメールアドレスで利用者を検索し、`PasswordEncoder#matches`でパスワードを照合する |
| APIの呼び出し | `authHeaderInterceptor`が、全てのリクエストに`X-User-Id`ヘッダ（保持している利用者ID）を付与する。未ログインの場合は付与しない | `AuthInterceptor`が`X-User-Id`の値で利用者を検索し、見つかった利用者（利用者ID・名前・利用者区分コード）をリクエスト単位の`AuthContext`に設定する。Controller・Serviceは`AuthContext#getCurrentUser`で参照する |
| ログアウト | `LoginUserStore#logout`が保持内容と`localStorage`を消去し、SC-010へ遷移する | 処理なし |
| 画面遷移の制御 | `authGuard`が未ログインでの遷移をSC-010へ、`adminGuard`が管理者以外の管理者向け画面への遷移をSC-020へ振り向ける | - |

- `AuthInterceptor`は`/api/**`に適用し、ログイン（`POST /api/login`）・利用者登録（`POST /api/users`）・稼働確認（`GET /api/ping`）を対象から除く。
- APIドキュメント（`/swagger-ui/**`・`/v3/api-docs`）は`/api/**`に含まれないため、認証の対象外となる。Swagger UIからAPIを試せるよう、認証を要するAPIには`X-User-Id`の入力欄を追加する（`SwaggerAuthHeaderCustomizer`）。

### 5.2 認証エラーとなる条件

`AuthInterceptor`は、次のいずれかの場合に`UnauthorizedException`（401、E-A-001）を発生させる。

- `X-User-Id`ヘッダが無い
- `X-User-Id`の値が数値でない
- 該当する利用者が存在しない
- 該当する利用者が退会済み（`users.anonymized_at`に値がある）

### 5.4 画面側での制御

| 状況 | 画面の動作 |
|---|---|
| 未ログインで、ログインが必要な画面を開いた | `authGuard`がSC-010へ遷移させる |
| 一般利用者が管理者向けの画面を開いた | `adminGuard`がSC-020へ遷移させる |
| 権限のない操作のボタン | 表示しない（他人のコメントの削除、管理者に対する申込フォーム等。`docs/30_詳細設計/30_画面詳細設計書.md`の各項目の表示条件） |
| APIが401（認証エラー）を返した | `httpErrorInterceptor`が、`LoginUserStore#logout`でログイン状態を解除し、SC-010へ遷移させる。ログインAPI（AP-010）の401は対象外とし、SC-010がメッセージを表示する |
| APIが403（権限エラー）を返した | メッセージをその場に表示する。画面遷移は行わない |

## 6. ログ出力

出力対象の基準・レベル・出力しない情報は`docs/20_基本設計/24_方式設計書.md`6章に定める。ログはSLF4J（Spring Bootの標準）で出力し、項目はメッセージ内に`キー=値`の形式で含める。

### 6.1 操作ログ（INFO）

Service層の処理が成功した時点で出力する。

| API | 操作 | 出力する理由（`docs/20_基本設計/24_方式設計書.md`6.2） | メッセージ |
|---|---|---|---|
| AP-010 | ログイン成功 | データベースに痕跡が残らない | `ログイン成功 userId={}` |
| AP-012 | パスワード変更 | 変更内容が残らない | `パスワード変更完了 userId={}` |
| AP-013 | 退会（匿名化） | 実行者が残らない | `利用者匿名化完了 userId={} 実行者userId={}` |
| AP-052 | コメント削除（物理削除） | 行が消える。実行者が残らない | `コメント物理削除完了 commentId={} eventId={} 実行者userId={}` |
| AP-052 | コメント削除（論理削除） | 実行者が残らない | `コメント論理削除完了 commentId={} eventId={} 実行者userId={}` |
| AP-120 | イベント登録 | 実行者が残らない | `イベント登録完了 eventId={} 実行者userId={}` |
| AP-121 | イベント更新 | 実行者が残らない | `イベント更新完了 eventId={} 実行者userId={}` |
| AP-122 | イベント削除 | 実行者が残らない | `イベント削除完了 eventId={} 実行者userId={}` |
| AP-124 | イベント復元 | 実行者が残らない | `イベント復元完了 eventId={} 実行者userId={}` |
| AP-126 | チェックイン | 実行者が残らない | `チェックイン完了 applicationId={} 実行者userId={}` |
| AP-130 | 申込実績のCSV出力 | データベースに痕跡が残らない | `申込実績CSV出力完了 件数={} 実行者userId={}` |
| AP-145 | 管理者アカウント登録 | 実行者が残らない | `管理者アカウント登録完了 userId={} 実行者userId={}` |
| AP-146 | 管理者権限の降格 | 実行者が残らない | `管理者権限降格完了 userId={} 実行者userId={}` |

### 6.2 エラーログ（WARN・ERROR）

| 場面 | 出力する場所 | レベル | 書式 | 例 |
|---|---|---|---|---|
| 入力エラー、業務ルール違反、データ未検出、認証・権限エラー | `GlobalExceptionHandler` | WARN | `userId={} {メソッド} {パス} {メッセージ}` | `userId=1 POST /api/applications すでに申し込み済みです` |
| リクエスト過多 | `RateLimitInterceptor` | WARN | `E-R-001 リクエストが多すぎます ip={} method={} path={}` | - |
| 想定外の例外 | `GlobalExceptionHandler` | ERROR | `E-S-001 想定外のエラー userId={} {メソッド} {パス}`＋スタックトレース | - |

- 未ログインでのエラーは`userId=-`と出力する。
- ログイン失敗（E-A-006）では、入力されたメールアドレス・パスワードを出力しない。
- 入力エラーでは、入力された値を出力しない（メッセージのみ）。
