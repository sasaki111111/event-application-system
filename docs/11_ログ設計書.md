# 11_ログ設計書

## 1. 概要

本書は、本システムのログ出力について、種類・レベルの使い分け・出力フォーマット・出力タイミングを定義するログ設計書である。`docs/08_エラー設計書.md`のログレベル方針と一致させる。

本書の内容は、SLF4J（Spring Bootの標準ログ実装）により各Service・`GlobalExceptionHandler`に実装済みである。

## 11-1 ログの種類

| 種類 | 目的 | 出力する場所 |
|---|---|---|
| アプリケーションログ | 処理が正しく動いているかを確認する（開始・終了・件数等） | Service層 |
| エラーログ | エラーの原因を調査する | `GlobalExceptionHandler` |
| 操作ログ | 誰がいつ何をしたかを後から確認する（11-5参照） | Service層（登録・更新・削除系メソッドの完了時） |

## 11-2 ログレベルの使い分け

`docs/08_エラー設計書.md`8-3のログレベル列と一致させる。

| レベル | 出すとき | 対応する例外・状況（8-3参照） |
|---|---|---|
| DEBUG | 開発中の詳しい調査用（本番相当の環境では出さない） | SQLのパラメータ、メソッドの引数等 |
| INFO | 正常な処理の要所 | イベント登録・申込・チェックイン等の完了（11-4参照） |
| WARN | 想定内だが注意が必要なとき（業務例外） | `UnauthorizedException`・`ForbiddenException`・`NotFoundException`・`BusinessException`・入力エラー系（E-V-／E-B-／E-A-のいずれも該当、8-3） |
| ERROR | 処理が失敗したとき（システム例外） | 上記のいずれにも該当しない想定外の例外（E-S-001、スタックトレースも出す） |

## 11-3 出力フォーマット

### エラーログ（`GlobalExceptionHandler`、WARN／ERROR）

```text
2026-10-01 10:15:30.123 WARN  [GlobalExceptionHandler] userId=1 POST /api/applications すでに申し込み済みです
```

| 項目 | 例 |
|---|---|
| 日時・ログレベル・クラス名 | SLF4J（Logback）の標準出力に準拠 |
| ログイン中利用者ID | `userId=1`（未ログインでのアクセス失敗時は`userId=-`） |
| API（メソッドとパス） | `POST /api/applications` |
| メッセージ | 例外の持つメッセージそのもの（`docs/08_エラー設計書.md`参照。業務例外のメッセージ文自体にはエラーIDを含めない） |

想定外の例外（ERROR、E-S-001）のみ、メッセージの先頭にエラーIDを付け、スタックトレースも併せて出力する（例：`E-S-001 想定外のエラー userId=1 POST /api/events`）。同様に、`RateLimitInterceptor`（E-R-001）もエラーIDを付けて出力する。

### 操作ログ（Service層、INFO）

```text
2026-10-01 10:15:30.123 INFO  [ApplicationService] 申込登録完了 userId=1 applicationId=30 eventId=10 status=受付済
```

項目はメッセージ内に `キー=値` の形式で含める（11-4・11-5参照）。

## 11-4 出力タイミング一覧

代表的なAPIについて、成功時・エラー時それぞれのログ出力タイミングを示す。全APIに同様の方針を適用する。

| API ID | タイミング | レベル | メッセージ例 |
|---|---|---|---|
| AP-07 | イベント登録成功 | INFO | `イベント登録完了 userId=2 eventId=10 name=... capacity=20` |
| AP-12 | 申込成功（受付済） | INFO | `申込登録完了 userId=1 applicationId=30 eventId=10 status=受付済` |
| AP-12 | 申込成功（キャンセル待ち） | INFO | `申込登録完了 userId=1 applicationId=31 eventId=10 status=キャンセル待ち` |
| AP-12 | 定員判定以前のエラー（E-B-001〜E-B-005等） | WARN | 例外の持つメッセージ（8-3参照） |
| AP-14 | キャンセル成功（繰り上げ発生） | INFO | `申込キャンセル完了 userId=1 applicationId=30 繰り上げapplicationId=32` |
| AP-14 | 取消不可（E-B-010） | WARN | 例外の持つメッセージ（例：`取消できません`） |
| AP-21 | コメント削除（物理削除） | INFO | `コメント物理削除完了 userId=1 commentId=8` |
| AP-21 | コメント削除（論理削除） | INFO | `コメント論理削除完了 userId=1 commentId=8` |
| AP-22 | CSV出力完了 | INFO | `申込実績CSV出力完了 userId=2 出力条件=開催日時順 件数=120` |

| 全API | 権限エラー（E-A-002等） | WARN | 例外の持つメッセージ（例：`権限がありません`） |
| 全API | 想定外の例外 | ERROR | `E-S-001 想定外のエラー userId=1 ...`＋スタックトレース |
| 書き込み系全API | リクエスト過多（E-R-001） | WARN | `E-R-001 リクエストが多すぎます ip=... method=... path=...`（`RateLimitInterceptor`） |

## 11-5 操作ログの対象

「誰が・いつ・何をしたか」を記録する対象は、データを変更する操作（登録・更新・削除）とする。

| 操作 | 記録する項目 |
|---|---|
| イベントの登録・編集・削除・復元（管理者） | 利用者ID、日時、操作種別、イベントID、結果 |
| 申込の登録・キャンセル・チェックイン | 利用者ID、日時、操作種別、申込ID、結果 |
| お気に入りの登録・解除 | 利用者ID、日時、操作種別、イベントID、結果 |
| コメントの投稿・削除 | 利用者ID、日時、操作種別、コメントID、結果（物理削除／論理削除の別） |
| 利用者登録・管理者アカウント登録 | 利用者ID（登録された側／登録した管理者側）、日時、結果 |
| 申込実績CSVの出力（管理者） | 利用者ID、日時、出力条件（並び順）、件数 |

## 11-6 出力してはいけない情報

| 情報 | 扱い |
|---|---|
| パスワード・トークン | 本システムはパスワード認証を行わないため対象データ自体が存在しない |
| メールアドレス等の個人情報 | 出力しない（利用者を特定する必要がある場合は利用者IDで代用する） |
| コメント本文・アンケート回答の全文 | 出力しない（必要な場合は文字数や存在有無のみを記録する） |
| リクエストの全文 | 出力しない（必要な項目のみを選んで出す） |
| スタックトレース | ERRORレベル（想定外の例外）のときのみ出力し、WARN以下（業務例外）では出力しない |

## 11-7 出力先・保管（想定）

現時点ではコンソール出力のみ（Spring Bootの標準設定）。ファイルへの出力・保存は未設定であり、以下は今後ファイル出力を追加する場合の想定方針である。

| 項目 | 方針 |
|---|---|
| 出力先 | ファイル（例：`logs/app.log`）への出力を想定 |
| ファイルの切り替え | 日ごとに新しいファイルにする |
| 保持期間 | 定量的な方針は定めない（`docs/10_非機能設計書.md`10-6と同様の位置づけ） |
| 設定場所 | `logback-spring.xml`（追加時に決定） |
| 実装方式 | SLF4J（Spring Bootの標準ログ実装）。各Service・`GlobalExceptionHandler`に`Logger`を実装済み |
