# 11_ログ設計書

## 1. 概要

本書は、本システムのログ出力について、種類・レベルの使い分け・出力フォーマット・出力タイミングを定義するログ設計書である。`docs/08_エラー設計書.md`のログレベル方針と一致させる。

**本書の位置づけ（重要）**：現時点の実装には、ログ出力の仕組み（SLF4J等によるログ出力コード）が一切存在しない。本書は、今後ログ出力を実装する際の目標設計として先行して整備するものであり、本書の内容はまだコードに反映されていない。実装への反映は別途の決定・作業として行う（`docs/12_設計確定時の確認事項.md`に決定事項として記録する）。

## 11-1 ログの種類

| 種類 | 目的 | 出力する場所（想定） |
|---|---|---|
| アプリケーションログ | 処理が正しく動いているかを確認する（開始・終了・件数等） | Service層 |
| エラーログ | エラーの原因を調査する | `GlobalExceptionHandler` |
| 操作ログ | 誰がいつ何をしたかを後から確認する（11-5参照） | Service層（登録・更新・削除系メソッドの完了時） |

## 11-2 ログレベルの使い分け

`docs/08_エラー設計書.md`9-3のログレベル列と一致させる。

| レベル | 出すとき | 対応する例外・状況（9-3参照） |
|---|---|---|
| DEBUG | 開発中の詳しい調査用（本番相当の環境では出さない） | SQLのパラメータ、メソッドの引数等 |
| INFO | 正常な処理の要所 | イベント登録・申込・チェックイン等の完了（11-4参照） |
| WARN | 想定内だが注意が必要なとき（業務例外） | `UnauthorizedException`・`ForbiddenException`・`NotFoundException`・`BusinessException`・入力エラー系（E-V-／E-B-／E-A-のいずれも該当、9-3） |
| ERROR | 処理が失敗したとき（システム例外） | 上記のいずれにも該当しない想定外の例外（E-S-001、スタックトレースも出す） |

## 11-3 出力フォーマット

```text
2026-10-01 10:15:30.123 WARN  [ApplicationService] userId=1 POST /api/applications E-B-003 すでに申し込み済みです eventId=5
```

| 項目 | 例 |
|---|---|
| 日時 | `2026-10-01 10:15:30.123` |
| ログレベル | `WARN` |
| クラス名 | `ApplicationService` |
| ログイン中利用者ID | `userId=1`（未ログインでのアクセス失敗時は`userId=-`） |
| API（メソッドとパス） | `POST /api/applications` |
| エラーID（エラー時のみ） | `E-B-003`（`docs/08_エラー設計書.md`9-3参照） |
| メッセージと関連する値 | `すでに申し込み済みです eventId=5` |

## 11-4 出力タイミング一覧（想定）

代表的なAPIについて、成功時・エラー時それぞれのログ出力タイミングを示す。全APIに同様の方針を適用する。

| API ID | タイミング | レベル | メッセージ例 |
|---|---|---|---|
| AP-07 | イベント登録成功 | INFO | `イベント登録完了 eventId=10 name=... capacity=20` |
| AP-12 | 申込成功（受付済） | INFO | `申込登録完了 applicationId=30 eventId=10 status=受付済` |
| AP-12 | 申込成功（キャンセル待ち） | INFO | `申込登録完了 applicationId=31 eventId=10 status=キャンセル待ち` |
| AP-12 | 定員判定以前のエラー（E-B-001〜E-B-005等） | WARN | 9-3のメッセージ列のとおり |
| AP-14 | キャンセル成功（繰り上げ発生） | INFO | `申込キャンセル完了 applicationId=30 促進applicationId=32` |
| AP-14 | 取消不可（E-B-010） | WARN | `E-B-010 取消できません applicationId=30` |
| AP-21 | コメント削除（物理削除） | INFO | `コメント物理削除完了 commentId=8` |
| AP-21 | コメント削除（論理削除） | INFO | `コメント論理削除完了 commentId=8` |
| AP-22 | CSV出力完了 | INFO | `申込実績CSV出力完了 件数=120` |
| 全API | 未ログイン（E-A-001） | WARN | `E-A-001 認証が必要です` |
| 全API | 権限エラー（E-A-002等） | WARN | `E-A-00x 権限がありません userId=1` |
| 全API | 想定外の例外 | ERROR | `E-S-001 想定外のエラー`＋スタックトレース |

## 11-5 操作ログの対象（想定）

「誰が・いつ・何をしたか」を記録する対象は、データを変更する操作（登録・更新・削除）とする。

| 操作 | 記録する項目 |
|---|---|
| イベントの登録・編集・削除・復元（管理者） | 利用者ID、日時、操作種別、イベントID、結果 |
| 申込の登録・キャンセル・チェックイン | 利用者ID、日時、操作種別、申込ID、結果 |
| お気に入りの登録・解除 | 利用者ID、日時、操作種別、イベントID、結果 |
| コメントの投稿・削除 | 利用者ID、日時、操作種別、コメントID、結果（物理削除／論理削除の別） |
| 利用者登録・管理者アカウント登録 | 利用者ID（登録された側／登録した管理者側）、日時、結果 |
| 申込実績CSVの出力（管理者） | 利用者ID、日時、出力条件（並び順）、件数 |

## 11-6 出力してはいけない情報

| 情報 | 扱い |
|---|---|
| パスワード・トークン | 本システムはパスワード認証を行わないため対象データ自体が存在しない |
| メールアドレス等の個人情報 | 出力しない（利用者を特定する必要がある場合は利用者IDで代用する） |
| コメント本文・アンケート回答の全文 | 出力しない（必要な場合は文字数や存在有無のみを記録する） |
| リクエストの全文 | 出力しない（必要な項目のみを選んで出す） |
| スタックトレース | ERRORレベル（想定外の例外）のときのみ出力し、WARN以下（業務例外）では出力しない |

## 11-7 出力先・保管（想定）

| 項目 | 方針 |
|---|---|
| 出力先 | コンソールおよびファイル（例：`logs/app.log`） |
| ファイルの切り替え | 日ごとに新しいファイルにする |
| 保持期間 | 定量的な方針は定めない（`docs/10_非機能設計書.md`10-6、D-11と同様の位置づけ） |
| 設定場所 | Spring Bootの`application.yml`または`logback-spring.xml`（実装時に決定） |
| 実装方式 | SLF4J（Spring Bootの標準ログ実装）を使用する想定。各Service・`GlobalExceptionHandler`に`Logger`を追加する必要がある（現時点では未追加、本書冒頭「本書の位置づけ」参照） |
