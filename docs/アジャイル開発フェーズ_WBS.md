# アジャイル開発フェーズ WBS

作成：2026-09-18 ／ v1.2（既存の完了分も含めて合計200hで再集計）

## 0. 位置づけ

`開発演習_WBS.xlsx`（フェーズA〜I、技術仕様書の必須ライン＋機能追加を完了済み）とは**別の、新規のWBS**。今回は**プロジェクト開始からここまでの実績（相当）＋これから追加開発する分」を合わせて、合計約200時間**の中でどう配分されているか／されるかを整理する。

### 前提の整理

- 5〜6人チームなら合計約200〜240時間相当（技術仕様書§7：1人あたり40.5h×5〜6人）の作業量になる、という比較基準。
- 「これから200h使える」のではなく、**すでに使った分（既存の完了分）を差し引いた残りで、新規アジャイルフェーズを進める**。
- ここでの時間は実測値ではなく、規模から逆算した目安（見積もり）。発表資料スライド7「AI利用効果」では、この見積もりと実際の感覚の差も振り返りの材料にできる。

### 3.2 プロダクトバックログ（20h以内に収まる規模で選定）

52hの元バックログ案から、48h予算に収まるよう絞り込んだ版。**採用するかどうか・組み合わせは個人の判断で決めてよい。**

| No | 項目 | 概要 | 目安時間 |
|---|---|---|---|
| B-1 | ページネーション | イベント件数が増えた場合に一覧を分割表示 | 8h |
| B-4 | 開催間近の強調表示 | 申込済みイベントのうち開催が近いものを一覧・マイページで目立たせる | 10h |
| B-2 | カテゴリ・タグ絞り込み | イベントにカテゴリを付け、検索画面で絞り込めるようにする | 20h |

> B-1＋B-4（計18h）で20h枠にほぼ収まる。B-2単体（20h）を選ぶ場合はB-1・B-4を見送る。B-3（お気に入り、22h）・B-5（画像、18h）・B-6（監査ログ、37h）・B-7（通知欄、20h）は今回の48h予算では入りきらないため、次回以降のバックログとして持ち越す。

### 3.3 Definition of Done（機能追加1項目あたり）

- [ ] 画面→API→DBが連携して動作する
- [ ] 追加した業務ロジックについて、正常系・異常系の単体テストがある
- [ ] 対応する設計書（要件定義書／API設計書／テーブル定義書／詳細設計書のうち該当箇所）が更新されている
- [ ] `docs/コードベース解説.md`に新規ファイルの説明を追記した
- [ ] 変更がコミット・push済みである

## 4. 予算が変わった場合の調整

- 48hより余裕がある場合：§3.2で見送ったB-3・B-5・B-6・B-7から追加する（優先度は個人の判断）。
- 48hより厳しい場合：まずバッファ（3h）を削り、次にB-1/B-4のどちらか一方に絞る。発表準備（15h）とテスト（8h）は完了条件に直結するため、削るなら機能追加側を優先して削る。
