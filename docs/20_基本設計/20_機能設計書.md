# 20_機能設計書

## 1. 概要

本書は、`docs/10_要件定義/10_要件定義書.md`に定めた各機能（F-010〜F-150）を、どの画面・どのAPI・どのテーブルで実現するか、および誰が利用できるかを定義する基本設計書である。機能・画面・API・データのつながりを追うための起点とする。

| 知りたいこと | 参照先 |
|---|---|
| 機能の目的・できること・業務ルール | `docs/10_要件定義/10_要件定義書.md` |
| 画面の一覧・遷移・各画面でできること | `docs/20_基本設計/21_画面基本設計書.md` |
| データの構造 | `docs/20_基本設計/22_テーブル定義書.md` |
| APIの一覧・共通仕様 | `docs/20_基本設計/23_API基本設計書.md` |
| 認証・エラー・ログ・非機能の方式 | `docs/20_基本設計/24_方式設計書.md` |
| 画面の項目・入力チェック・データの取得元 | `docs/30_詳細設計/30_画面詳細設計書.md` |
| APIの入出力項目 | `docs/30_詳細設計/31_API詳細設計書.md` |
| 処理の順序・判定・排他制御 | `docs/30_詳細設計/32_処理詳細設計書.md` |
| エラー一覧・ログ出力一覧 | `docs/30_詳細設計/33_共通詳細設計書.md` |

## 3. 機能とテーブルの対応（CRUD）

各機能が、各テーブル（`docs/20_基本設計/22_テーブル定義書.md`）を作成（C）・参照（R）・更新（U）・削除（D）のどれで使うかを示す。Dは行の物理削除を表し、論理削除・匿名化・状況の変更はUとして示す。

| F-013 | 利用者の退会（匿名化） | R・U | | | | | | R |
| F-020 | イベント一覧・検索 | | R | | R | R | | |
| F-021 | イベント詳細確認 | | R | R | R | R | | |
| F-022 | イベント申込 | R | R | R | C・R | | | R |

- 「コードマスタ」は`roles`・`application_statuses`を指す。利用者区分・申込状況の表示名を返す機能で参照する。

## 4. 権限

### 4.1 利用者区分

| 利用者区分 | コード | 説明 |
|---|---|---|
| 一般利用者 | 1 | イベントを閲覧・申込・お気に入り登録・コメント投稿する利用者 |
| 管理者 | 2 | イベントの登録・変更・削除・復元、当日受付、申込実績の確認・出力、利用者の管理を行う利用者 |

コードの定義は`docs/20_基本設計/22_テーブル定義書.md`7章を正とする。

### 4.4 APIごとの権限

APIごとの認証の要否・実行できる利用者は、`docs/20_基本設計/23_API基本設計書.md`3.2の「認証」「認可」列を正とする（本書には重複して記載しない）。

### 4.5 権限を判定する場所

- 画面側の制御（画面への遷移を防ぐ、ボタンを表示しない）は、利用者に不要な操作を見せないためのものであり、それだけでは安全ではない。
- サーバー側では、画面側の制御とは独立して、全てのAPIで認証・認可を必ず判定する。
- 判定の実装方法は`docs/30_詳細設計/33_共通詳細設計書.md`に定める。
