# 21_画面基本設計書

## 1. 概要

本書は、イベント申込システムが提供する画面の一覧、画面間の遷移、および各画面の目的・表示内容・できる操作を定義する基本設計書である。`docs/10_要件定義/10_要件定義書.md`の各機能を、どのような画面で提供するかを定める。

各画面の項目定義（部品の種類、必須、桁数、初期値、データの取得元）、イベント処理、入力チェック、エラー時の表示は`docs/30_詳細設計/30_画面詳細設計書.md`に定める。機能・APIとの対応、画面ごとの権限は`docs/20_基本設計/20_機能設計書.md`に定める。

## 2. 共通仕様

- **ログイン制御**：SC-010（ログイン・利用者登録）とSC-900（該当ページなし）を除く全ての画面は、ログイン状態でなければ利用できない。未ログインでアクセスした場合はSC-010へ案内する。
- **管理者専用画面の制御**：管理者向け画面（SC-110〜SC-150）は、管理者としてログインしている場合にのみ利用できる。一般利用者がアクセスした場合はSC-020（イベント一覧）へ案内する。
- **共通ナビゲーション**：ログイン中は画面上部に共通のナビゲーションを表示する。

  | 利用者区分 | 表示する導線 |
  |---|---|
  | 一般利用者 | イベント一覧（SC-020）／イベント検索（SC-021）／マイページ（SC-030）／パスワード変更（SC-011）／ログアウト |
  | 管理者 | ダッシュボード（SC-110）／イベント管理（SC-120）／申込状況・実績（SC-130）／利用者管理（SC-140）／コメント管理（SC-150）／パスワード変更（SC-011）／ログアウト |

- **エラー表示**：API呼び出しに失敗した場合、サーバーから返されたメッセージを優先して表示し、無い場合は画面ごとに定めた既定のメッセージを表示する。
- **通信不可時の表示**：サーバーと通信できない場合は、「サーバーに接続できません。バックエンドが起動しているか確認してください。」と表示する。
- **区分値の表示**：利用者区分・申込状況は、APIが返す表示名をそのまま表示する（`docs/20_基本設計/23_API基本設計書.md`2.8）。
- **確認**：取り消せない、または影響の大きい操作（申込キャンセル、イベント削除・復元、コメント削除、退会、管理者権限の降格、チェックインの再実行）は、実行前に確認を求める。

## 3. 画面一覧

### 3.1 画面IDの採番ルール

画面IDは「SC-」＋3桁の番号とし、画面のまとまりごとに10番単位で割り当てる。百の位は利用者の範囲（0：全利用者向け、1：管理者向け、9：共通）を表す。画面を追加する場合は、該当するまとまりの空き番号を使用し、既存の番号は変更・再利用しない。

| 番号の範囲 | 画面のまとまり |
|---|---|
| 010番台 | 認証・アカウント |
| 020番台 | イベントの閲覧・申込 |
| 030番台 | マイページ |
| 110番台 | 管理：概況 |
| 120番台 | 管理：イベント |
| 130番台 | 管理：実績 |
| 140番台 | 管理：利用者 |
| 150番台 | 管理：コメント |
| 900番台 | 共通 |

### 4.2 イベント詳細画面の「戻る」導線

SC-022（イベント詳細・申込）は、遷移元の画面に応じて「戻る」導線の遷移先を切り替える。SC-021（イベント検索）から遷移してきた場合はSC-021へ、それ以外の場合はSC-020（イベント一覧）へ戻る。

### 4.3 申込完了画面への遷移

SC-023（申込完了）は、SC-020またはSC-022での申込成功に伴う遷移によってのみ、申込結果を表示できる。この遷移を経ずに直接アクセスした場合は、申込結果を表示できない旨を表示する。申込直後の画面をそのまま再読み込みした場合は、申込結果を引き続き表示する。

### 4.4 管理者によるイベント一覧・詳細の閲覧

管理者向けの共通ナビゲーションには、SC-020（イベント一覧）・SC-021（イベント検索）・SC-030（マイページ）への導線を設けない。ただし管理者もログイン中の利用者であるため、URLを直接指定すればこれらの画面を閲覧できる。SC-020・SC-022では申込フォームを表示せず、管理者は申込できない旨を表示する。

## 5. 画面ごとの概要

各画面について、画面イメージ、目的、表示項目、入力項目、ボタン、操作、使用するAPIを示す。画面イメージ上の丸数字は、`docs/30_詳細設計/30_画面詳細設計書.md`の項目定義のNoに対応する。項目ごとの詳細、入力チェック、エラー時の表示は`docs/30_詳細設計/30_画面詳細設計書.md`に定める。

### SC-010 ログイン・利用者登録

![SC-010 ログイン・利用者登録](images/SC-010_1.png)

- **目的**：メールアドレスとパスワードによるログイン、または名前・メールアドレス・パスワードによる新規利用者登録と、そのままのログイン。
- **表示項目**：ログインフォーム、新規登録フォーム。
- **入力項目**：ログイン（メールアドレス、パスワード）、新規登録（名前、メールアドレス、パスワード）。パスワードは入力した文字を伏せて表示する。
- **ボタン**：「ログイン」、「登録してログイン」。
- **操作**：利用者がメールアドレスとパスワードを入力して「ログイン」を押下すると、ログインAPI（AP-010）を呼び出す。初めて利用する利用者が名前・メールアドレス・パスワードを入力して「登録してログイン」を押下すると、利用者登録API（AP-011）を呼び出し、成功後は登録内容でログイン状態とする。
- **API**：AP-010（ログイン）、AP-011（利用者登録）。
- **正常時**：ログイン・登録に成功すると、管理者はSC-110（ダッシュボード）へ、一般利用者はSC-020（イベント一覧）へ遷移する。

### SC-011 パスワード変更

![SC-011 パスワード変更](images/SC-011_1.png)

- **目的**：ログイン中の利用者が、自分のパスワードを変更する。
- **表示項目**：パスワードの条件（8文字以上72文字以下、英字と数字をそれぞれ1文字以上）の案内。
- **入力項目**：現在のパスワード、新しいパスワード、新しいパスワード（確認用）。いずれも入力した文字を伏せて表示する。
- **ボタン**：「変更する」。
- **操作**：利用者が各項目を入力して「変更する」を押下すると、パスワード変更API（AP-012）を呼び出す。
- **API**：AP-012（パスワード変更）。
- **正常時**：変更が完了した旨を表示する。ログイン状態は維持する。
- **遷移**：共通ナビゲーションの「パスワード変更」から遷移する（一般利用者・管理者とも）。

### SC-020 イベント一覧

*一覧表示。2件目は詳細を展開した状態、3件目は開催済みのイベント*

![SC-020 イベント一覧](images/SC-020_1.png)

*カレンダー表示*

![SC-020 イベント一覧](images/SC-020_2.png)

- **目的**：全てのイベントを一覧表示し、その場で詳細を確認しながら申込・お気に入り登録を行う。
- **並び順**：一覧形式では、開催前のイベントを先に、開催済み（開催日時が現在時刻以前）のイベントを末尾にまとめて表示する。開催前・開催済みそれぞれの中では、選択した並び順（既定は開催日時順）に従う。カレンダー形式には適用しない。
- **表示項目**：表示形式の切替（一覧／カレンダー）。一覧形式ではイベント名、受付状況、お気に入りの状態、お気に入り数、開催日時、場所、申込状況（受付済数／定員）。カレンダー形式では月単位のカレンダーに、各開催日のイベントを表示する。
- **入力項目**：申込フォーム（詳細表示時）として、参加区分（区分が設定されたイベントのみ）、アンケート回答（アンケートが設定されたイベントのみ）。
- **ボタン**：表示形式切替、並び替え（一覧形式のみ。開催日時順／申込数の多い順／お気に入り数の多い順／申込締切が近い順）、お気に入りの登録・解除、詳細の展開・収納、申込（残り枠が無い場合は「キャンセル待ちで申し込む」と表示）、カレンダーの前月・翌月切替。
- **操作**：利用者がイベント名を選択するとSC-022（イベント詳細）へ遷移する。参加区分・アンケートを入力し「申し込む」を押下すると、申込API（AP-030）を呼び出す。お気に入りボタンを押下すると、お気に入り登録・解除API（AP-040／AP-041）を呼び出す。並び替えを選択すると、取得済みの一覧データを画面側で並び替えて再表示する（APIの再取得は行わない）。
- **API**：AP-020（一覧取得）、AP-021（詳細取得）、AP-030（申込）、AP-040／AP-041（お気に入り登録・解除）、AP-042（お気に入り一覧取得）。
- **正常時**：申込に成功するとSC-023（申込完了）へ遷移する。お気に入りの状態とお気に入り数は、登録・解除に成功した時点で即座に画面へ反映する（一覧の再取得は行わず、表示中のお気に入り数を1増減する）。並び替えは即座に一覧表示へ反映する。
- **管理者の場合**：申込フォームは表示せず、管理者は申込できない旨を表示する。

### SC-021 イベント検索

![SC-021 イベント検索](images/SC-021_1.png)

- **目的**：取得済みのイベント情報を、キーワード・開催日の範囲で絞り込んで確認する。
- **並び順**：イベント一覧（SC-020）と同じく、開催前のイベントを先に、開催済み（開催日時が現在時刻以前）のイベントを末尾にまとめて表示する。開催前・開催済みそれぞれの中では、選択した並び順（既定は開催日時順）に従う。
- **表示項目**：検索フォーム、該当件数、イベントのカード一覧（イベント名、開催日時、場所、受付状況、お気に入り数を含み、詳細確認・申込への導線のみを持ち、その場での申込操作は行わない）。
- **入力項目**：キーワード（イベント名・場所を対象、任意）、開催日（から・まで、任意）。
- **ボタン**：「条件をクリア」、並び替え（開催日時順／申込数の多い順／お気に入り数の多い順／申込締切が近い順）。
- **操作**：利用者が検索条件を入力すると、画面上で該当するイベントに絞り込んで表示する。並び替えを選択すると、絞り込み結果を画面側で並び替えて再表示する（APIの再取得は行わない）。イベント名を選択するとSC-022（イベント詳細）へ遷移する。
- **API**：AP-020（一覧取得）、AP-040／AP-041（お気に入り登録・解除）、AP-042（お気に入り一覧取得）。
- **正常時**：条件に合致するイベントを一覧表示する。
- **遷移**：この画面から遷移した場合、SC-022の「戻る」導線はこの画面に戻る。

### SC-022 イベント詳細・申込

![SC-022 イベント詳細・申込](images/SC-022_1.png)

- **目的**：イベントの詳細情報を確認し、申込・お気に入り登録・コメントの投稿や削除を行う。
- **表示項目**：戻る導線（遷移元に応じてSC-020またはSC-021）、イベント名、お気に入りの状態、お気に入り数、イベント画像（設定時）、主催者名（設定時）、開催日時、場所、定員、残り枠、申込締切、受付状況、説明、コメント一覧（投稿者名・本文・投稿日時。自分の投稿または管理者には削除導線を表示。返信は親コメントの下にインデントして表示し、階層数に制限は無い。削除済みのコメントは本文が「このコメントは削除されました」等の表示に置き換わるが、投稿者名・返信は表示したまま残る）。
- **入力項目**：参加区分（区分が設定されたイベントのみ）、アンケート回答（アンケートが設定されたイベントのみ）、コメント本文、返信本文（各コメントの「返信」導線を開いた場合）。
- **ボタン**：お気に入りの登録・解除、申込（残り枠が無い場合は「キャンセル待ちで申し込む」）、コメント「投稿」、各コメントの「返信」（返信入力欄の開閉）、各コメントの「削除」（本人または管理者のみ表示。削除済みのコメントには表示しない）。
- **操作**：利用者が参加区分・アンケートを入力し「申し込む」を押下すると申込API（AP-030）を呼び出す。コメント本文を入力し「投稿」を押下するとコメント投稿API（AP-051）を呼び出す。各コメントの「返信」を押下すると返信入力欄を開き、入力して投稿すると対象コメントを返信先としてAP-051を呼び出す。
- **API**：AP-021（詳細取得）、AP-030（申込）、AP-040／AP-041（お気に入り登録・解除）、AP-050（コメント一覧取得）、AP-051（コメント投稿・返信）、AP-052（コメント削除）。
- **正常時**：申込に成功するとSC-023（申込完了）へ遷移する。お気に入りの状態とお気に入り数は、登録・解除に成功した時点で即座に画面へ反映する。コメント・返信の投稿・削除に成功すると一覧を更新する。

### SC-023 申込完了

![SC-023 申込完了](images/SC-023_1.png)

- **目的**：申込直後の結果（申込状況・申込日時）を表示する。
- **表示項目**：申込状況（受付済／キャンセル待ち）、申込日時。キャンセル待ちの場合は補足説明を表示する。
- **入力項目**：なし。
- **ボタン**：「イベント一覧へ」。
- **操作**：利用者が「イベント一覧へ」を押下するとSC-020（イベント一覧）へ遷移する。
- **API**：なし（直前の申込結果を表示する画面であり、専用の取得APIは持たない）。
