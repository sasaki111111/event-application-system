# G-3　STシナリオ（総合）

実施日：2026-09-15
方法：F-1（結合・動作確認）で実施したブラウザ操作の記録を、一般ユーザー視点1本・管理者視点1本の
STシナリオ（システムテスト・総合テストシナリオ）として整理したもの。F-1は実際にこの2本を
ログイン→ログアウトまで一つの連続したブラウザセッションで実行済みであり、単体機能の疎通だけでなく
「複数画面・複数APIをまたいだ一連の業務が最初から最後まで通しで動く」ことを検証している。

## STシナリオ1：一般ユーザー視点（イベント申込〜取消）

対応：要件定義書§5「一般シナリオ1・2」を1本の通しシナリオに統合したもの。

| # | 操作 | 使用する画面／API | 期待結果 | 結果 |
|---|---|---|---|---|
| 1 | `/login`でログイン | SC-01／（ダミー認証） | 一般ユーザーとしてログインし`/events`へ遷移 | OK |
| 2 | イベント一覧を見る | SC-02／API-01 | 開催日時・場所・申込状況・受付中/終了バッジが表示される | OK |
| 3 | イベントを選び詳細を見る | SC-02／API-02 | 開催日時・定員・残り枠・申込締切が表示される | OK |
| 4 | 「申し込む」を押す | SC-02／API-03 | 申込完了画面でステータス「受付済」を確認 | OK |
| 5 | マイページを開く | SC-03／API-04 | 直前の申込が一覧に反映されている | OK |
| 6 | 該当の申込を「取消」 | SC-03／API-05 | ステータスが「キャンセル済」に変化 | OK |
| 7 | ログアウト | 共通ナビ | `/login`に戻る | OK |

## STシナリオ2：管理者視点（イベント登録〜編集〜削除〜実績確認）

対応：要件定義書§5「管理者シナリオ1・2」を1本の通しシナリオに統合したもの。

| # | 操作 | 使用する画面／API | 期待結果 | 結果 |
|---|---|---|---|---|
| 1 | `/login`でログイン | SC-01／（ダミー認証） | 管理者としてログインし`/admin/events`へ遷移 | OK |
| 2 | 「新規登録」でイベントを作成 | SC-04／API-06 | 作成したイベントが一覧に反映される | OK |
| 3 | 作成したイベントを編集 | SC-04／API-07 | 変更内容（定員等）が保存・反映される | OK |
| 4 | 該当イベントを削除 | SC-04／API-08 | 一覧から消える | OK |
| 5 | 「申込状況・実績」を開く | SC-05／API-09 | イベント別の受付済数・充足率が表示される（`sort=accepted_desc`・`format=csv`はD-8で個別に確認済み） | OK |
| 6 | ログアウト | 共通ナビ | `/login`に戻る | OK |

## 総括

- 上記2本を、F-1で実際に1つの連続したブラウザセッション（一般ユーザーとしてログイン→操作→ログアウト→管理者としてログイン→操作→ログアウト）として通しで実行し、途中でフルリロードが発生しないこと・各操作結果が正しく次画面に反映されることを確認済み（`docs/F-1_結合動作確認記録.md`参照）。
- 個別の正常系・異常系の詳細（定員超過・二重申込・権限チェック等）はG-1（ユニットテスト）・G-2（結合テスト）・D-8（API疎通確認）でカバーしており、G-3はそれらを実際のユーザー操作の流れとして統合的に確認する位置づけ。
