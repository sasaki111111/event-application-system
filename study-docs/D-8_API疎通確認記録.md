## 詳細ログ

### API-01　GET /api/events　イベント一覧取得

- `status=all`（一般ユーザー）→ 200、全4件（非公開含む）を返却
- `status=open`（一般ユーザー）→ 200、`open:true`の3件のみ返却
- 認証ヘッダなし → 401「認証が必要です」
- 存在しないuserId → 401「認証が必要です」

### API-02　GET /api/events/{id}　イベント詳細取得

- 存在するID（1）→ 200、詳細項目（description・remaining含む）を返却
- 存在しないID（99999）→ 404「イベントが見つかりません」

### API-06　POST /api/events　イベント登録（管理者のみ）

- 管理者・正常データ → 201、作成されたイベントを返却
- 一般ユーザー → 403「権限がありません」（D-7で修正した通り、バリデーション前に権限チェックが先に走ることを確認）
- 管理者・必須項目未入力（`{}`） → 400「入力エラー」、5項目のerrors配列

### API-07　PUT /api/events/{id}　イベント編集（管理者のみ）

- 管理者・正常データ → 200、更新後の内容を返却
- 一般ユーザー → 403「権限がありません」
- 存在しないID → 404「イベントが見つかりません」

### API-03　POST /api/applications　イベント申込（一般のみ）

- 一般ユーザー・正常 → 201、申込情報を返却
- 管理者 → 403「管理者は申込できません」（D-7で修正した通り、バリデーション前に権限チェックが先に走ることを確認）
- 定員到達後の再申込（capacity=1に更新済みのイベントへ同一ユーザーが再度申込） → 400「定員に達しています」
- 存在しないeventId → 404「イベントが見つかりません」

### API-04　GET /api/my/applications　自分の申込一覧取得

- 一般ユーザー → 200、本人の申込のみ（キャンセル済含む）を返却
- 認証ヘッダなし → 401「認証が必要です」

### API-05　DELETE /api/applications/{id}　申込キャンセル

- 本人の申込 → 204、ステータスが「キャンセル済」に変化
- 他人の申込（管理者が一般ユーザーの申込をキャンセルしようとする） → 403「権限がありません」
- 存在しない申込ID → 404「申込が見つかりません」

### API-08　DELETE /api/events/{id}　イベント削除（管理者のみ）

- 一般ユーザー → 403「権限がありません」
- 管理者・申込が無いイベント → 204、削除成功
- 管理者・受付済の申込があるイベント → 400「申込があるため削除できません」（削除されない。カスケード削除ではなく拒否）
- 削除済みイベントへの再削除 → 404「イベントが見つかりません」
- 存在しないID → 404「イベントが見つかりません」

### API-09　GET /api/reports/applications　申込実績取得（管理者のみ）

- `format=json`（既定ソート：開催日時順） → 200、イベント別の受付数・充足率(fillRate)を返却
- `format=json&sort=accepted_desc`（チーム独自機能：人気度順ソート） → 200、acceptedCount降順で並び替えられていることを確認
- `format=csv` → 200、`Content-Disposition: attachment; filename=applications_report.csv`、`Content-Type: text/csv;charset=UTF-8`、UTF-8 BOM付きCSV（Excelで文字化けしない）。イベント名・申込者名・申込日時・ステータスの明細を確認
- 一般ユーザー → 403「権限がありません」

### 共通エラーハンドリング

- 未定義ルート（`/api/unknown-route`） → 404（Spring Bootデフォルトのエラーページ、`GlobalExceptionHandler`の対象外で仕様通り）
- 誤ったHTTPメソッド（`PATCH /api/events`） → 405
- 不正なJSON（構文エラー） → 400「リクエストの形式が不正です」

## 検証時に使用した一時データ

すべて確認後に削除済み、または元の状態に復元済み。

- 一時イベント（D8疎通確認用イベント、ID: 102〜106）→ すべてAPI-08または直接DELETEで削除済み
- 一時申込（ID: 16）→ 明示的にキャンセル済み（キャンセル後のイベントは受付済申込が無いため削除可能になった）
- 既存データ（イベントID 1〜4、ユーザー1の申込ID 6,7,8,13,14）への影響なしを確認
