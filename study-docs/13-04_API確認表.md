# 13-04 API確認表

[13_システム動作・実装対応チェックリスト.md](13_システム動作・実装対応チェックリスト.md)の補助資料。`docs/20_基本設計/23_API基本設計書.md`3.2の全35 APIについて、設計（`docs/30_詳細設計/31_API詳細設計書.md`）と実装の対応を1件ずつ整理する。

- 「呼び出し元」はフロントエンドのファイル（クラス）とメソッド、「処理」はController→Service→Repositoryの順に示す。
- 認可は`docs/30_詳細設計/33_共通詳細設計書.md`5.3、エラーIDは同3章を参照。管理者専用APIで一般利用者が呼んだ場合の403（E-A-002）は、各APIの「エラー」欄では省略する。
- 「テスト」は結合テスト仕様書（`docs/40_テスト/42_結合テスト仕様書.md`）の該当IDの接頭辞。すべて実施済み。
- Swagger UI（`/swagger-ui/index.html`）の各APIの説明は、Controllerの`@Operation`に記載している。

## 認証・アカウント（010番台）

### AP-010 ログイン `POST /api/login`

- **呼び出し元**：SC-010 `login/login.ts`の`login()` → `core/login-api.ts`（`LoginApiService`）の`login()`
- **Request**：`{ email, password }`。認証不要（`WebConfig`で`AuthInterceptor`の対象外）。回数制限の対象
- **入力チェック**：`LoginRequest`：`email`は`@NotBlank @Email`（E-V-001、前後の空白はDTOの生成時に除去）、`password`は`@NotBlank @Size(max=72)`（E-V-024）
- **処理**：`UserController#login` → `UserService#login`（`normalizeEmail` → `UserRepository#findByEmail` → 退会済み・ハッシュ値なし・`PasswordEncoder#matches`が偽なら401）→ INFOログ「ログイン成功」
- **応答（200）**：`UserResponse{ userId, name, email, roleCode, roleName, anonymizedAt }`（パスワード・ハッシュ値は含まない）
- **エラー**：未登録・パスワード不一致・退会済みは、いずれも401と同じメッセージ（R-22・E-A-006）
- **画面の処理**：`LoginUserStore.login(userId, roleCode)`で保存し、管理者は`/admin/dashboard`、一般利用者は`/events`へ遷移
- **テスト**：IT-AP010、UT-USR

### AP-011 利用者登録 `POST /api/users`

- **呼び出し元**：SC-010 `login.ts`の`register()` → `LoginApiService.register()`
- **Request**：`{ name, email, password }`。認証不要（`AuthInterceptor`の中でPOSTのみ認証を省略）
- **入力チェック**：`UserRegisterRequest`（E-V-002・E-V-003・E-V-025）
- **処理**：`UserController#register` → `UserService#register`（正規化 → `existsByEmail` → ハッシュ化して`role_code=1`で`save`）。成功のログは出さない
- **応答（201）**：`UserResponse`（常に一般利用者）
- **エラー**：メールアドレスの重複は400「この内容では登録できませんでした。ログインをお試しください」（E-B-015。重複の事実を断定しない）
- **画面の処理**：そのままログイン状態にして`/events`へ遷移。400＋`errors[]`は項目ごとに表示
- **テスト**：IT-AP011、IT-CMN-N02、UT-USR

### AP-012 パスワード変更 `PUT /api/my/password`

- **呼び出し元**：SC-011 `password-change/password-change.ts`の`submit()` → `LoginApiService.changePassword()`
- **Request**：`{ currentPassword, newPassword }`。対象はログイン中の利用者本人（利用者IDはリクエストに含めない）
- **入力チェック**：`PasswordChangeRequest`（E-V-026・E-V-027）。画面側で未入力・確認用との不一致を先に確認する
- **処理**：`UserController#changePassword` → `UserService#changePassword`（現在のパスワードを照合 → 新しいハッシュ値で上書き）→ INFOログ「パスワード変更完了」
- **応答**：204（ログイン状態は維持）
- **エラー**：現在のパスワードの不一致は400（R-23・E-B-023）
- **テスト**：IT-AP012、UT-USR

### AP-013 利用者の退会（匿名化） `DELETE /api/users/{id}`

- **呼び出し元**：SC-030 `my-applications.ts`の`withdraw()`（本人）、SC-141 `admin-user-detail.ts`の`anonymize()`（管理者） → `core/user-api.ts`（`UserApiService`）の`anonymize()`
- **認可**：本人、または管理者（判定は`UserService#anonymize`で行う。R-20・E-A-007）
- **処理**：`UserController#anonymize` → `UserService#anonymize`（存在確認 → 認可 → 管理者でないこと〔R-18〕→ 退会済みでないこと〔R-19〕→ `User#anonymize`〔名前・メールアドレスの置き換え、`password_hash`をNULL、`anonymized_at`を設定。R-24〕）→ INFOログ
- **応答（200）**：匿名化後の`UserResponse`
- **エラー**：存在しない404（E-B-018）、本人・管理者以外403（E-A-007）、対象が管理者400（E-B-021）、退会済み400（E-B-022）
- **画面の処理**：本人はログアウトして`/login`へ。管理者は表示を更新し「退会済み」を表示。以後、同じIDのリクエストは401
- **テスト**：IT-AP013、IT-CMN-E04、UT-USR

### AP-014 ログイン中利用者情報取得 `GET /api/whoami`

- **呼び出し元**：画面からは呼ばない（動作確認用）
- **処理**：`PingController#whoami`（Serviceを経由せず`AuthContext`の値と`CodeNameResolver`の表示名を返す。`docs/30_詳細設計/32_処理詳細設計書.md`2章の例外）
- **応答（200）**：`WhoAmIResponse{ userId, name, roleCode, roleName, admin }`
- **テスト**：IT-AP014
