# イベント申込システム

チーム開発演習（技術仕様書 v0.1 準拠・1人での教材作成テスト段階）の実装リポジトリ。

## 概要

一般ユーザーが開催中のイベントを一覧・カレンダー・キーワード検索で探し、お気に入り登録やコメント投稿（返信を含む）を行いながら参加を申し込む（参加区分・申込時アンケートへの回答に対応、定員超過時は自動的にキャンセル待ちとなり、キャンセル発生時は自動繰り上げ）。管理者はイベントの登録・編集・複製・削除（削除済みからの復元可）、当日受付（チェックイン、申込時アンケート回答の確認を含む）、申込実績の確認・CSV出力、利用者一覧・利用者詳細（申込・お気に入り・コメント履歴）の確認、全イベント横断のコメント管理、管理者アカウントの追加登録・管理者権限の降格・利用者の退会を行う。利用者は自分のパスワードの変更と退会ができる。メールアドレスとパスワードでログインして利用するWebアプリケーション（ログイン後の利用者の識別方式に制約があるため、学内利用を前提とする。詳細は方式設計書を参照）。

## 技術スタック

- フロントエンド：Angular（SPA）
- バックエンド：Spring Boot（パスワードのハッシュ化にspring-security-cryptoのBCryptを使用）
- データベース：MySQL
- AI活用：Claude Code

## セットアップ

### 事前に必要なソフト

| ソフト | バージョンの目安 |
|---|---|
| Java（JDK） | 21 |
| Node.js | 20系以降 |
| MySQL Server | 8.0 |
| Git | コードを取得する場合 |

別のPCで動かす場合は、まずこのリポジトリを取得する。

```
git clone https://github.com/sasaki111111/event-application-system.git
```

### フロントエンド（Angular）

```
cd frontend
npm install
npm start
```

### バックエンド（Spring Boot）

事前にMySQLに `eventapp` データベースと接続用ユーザーを作成しておく（B-4）。

```sql
CREATE DATABASE eventapp CHARACTER SET utf8mb4 COLLATE utf8mb4_ja_0900_as_cs;
CREATE USER 'eventapp_app'@'localhost' IDENTIFIED BY '<任意のパスワード>';
GRANT ALL PRIVILEGES ON eventapp.* TO 'eventapp_app'@'localhost';
```

`backend/src/main/resources/application-local.yml`（gitignore対象・各自作成）に接続情報を書く。

```yaml
spring:
  datasource:
    username: eventapp_app
    password: <上で設定したパスワード>
```

DDL・初期データを投入する（C-1・C-2、`--default-character-set=utf8mb4`を付けないと日本語のデータが文字化けする）。`schema.sql`は既存のテーブルを削除して作り直すため、**投入済みのデータは消える**。テーブル定義を変更した版に更新した場合も、この2つを流し直す。

```
mysql --default-character-set=utf8mb4 -u eventapp_app -p eventapp < backend/src/main/resources/db/schema.sql
mysql --default-character-set=utf8mb4 -u eventapp_app -p eventapp < backend/src/main/resources/db/seed.sql
```

起動:

```
cd backend
./mvnw spring-boot:run -Dspring-boot.run.profiles=local
```

> **コマンドプロンプト（cmd.exe）で実行する場合**：`./mvnw` の `./` はGit Bash／PowerShell向けの書き方で、cmd.exeでは付けずに実行する。
>
> ```
> cd backend
> mvnw spring-boot:run -Dspring-boot.run.profiles=local
> ```
>
> フロントエンド側の `npm install`／`npm start` はシェルを問わずそのまま使える。

起動後、`http://localhost:8080/api/ping` にアクセスして `pong` が返ることを確認できる（B-3の起動確認用エンドポイント）。起動ログにHikariCPの接続完了ログが出ればMySQL接続も確認できている（B-4）。

利用者の識別（B-5）の疎通確認は `http://localhost:8080/api/whoami` に `X-User-Id: 1`（一般ユーザー）または `X-User-Id: 2`（管理者）ヘッダを付けてアクセスする。ヘッダが無い・不正なIDの場合は401が返る。

起動後、`http://localhost:8080/swagger-ui.html` からAPIドキュメント（Swagger UI）を確認できる。認証不要な3 APIを除く全APIに`X-User-Id`ヘッダの入力欄が自動で追加されているので、一般ユーザーを試す場合は`1`、管理者を試す場合は`2`を指定すればSwagger UI単体で動作確認できる。 ログインAPI（`POST /api/login`）を試す場合は、メールアドレスとパスワードをリクエストに指定する。

### 自動テスト

```
cd backend
./mvnw test
```

```
cd frontend
npm test
```

- バックエンドのテストはインメモリDB（H2）を使うため、MySQLが起動していなくても実行できる。単体テスト（Service層）、結合テスト（API〜DB）に加え、`schema.sql`・`seed.sql`がエラー無く実行できることを確認するテスト（`SchemaScriptTest`）を含む。
- `./mvnw clean`がビルド出力フォルダ（`backend/target`）を削除できずに失敗する場合は、エディタのJava拡張機能等がフォルダを使用している。`clean`を付けずに実行するか、エディタを閉じてから実行する。

### 使い方

フロントエンド・バックエンドの両方を起動した状態で、ブラウザで `http://localhost:4200` を開く（`http://localhost:8080` はバックエンドのAPIのみで画面は無い）。

メールアドレスとパスワードでログインする。初期データの利用者は次のとおり（初期パスワードはいずれも `Test1234`）。

| 利用者 | メールアドレス | 初期パスワード |
|---|---|---|
| 一般ユーザー | `general@example.com` | `Test1234` |
| 管理者 | `admin@example.com` | `Test1234` |
| 退会の動作確認用（一般ユーザー） | `withdraw-test@example.com` | `Test1234` |

- 初めて利用する場合は、ログイン画面の新規登録欄から名前・メールアドレス・パスワードを入力して一般ユーザーを作成できる（作成されるのは常に一般ユーザー）。
- パスワードは8文字以上72文字以下で、英字と数字をそれぞれ1文字以上含める。
- ログイン後は、画面上部の「パスワード変更」から自分のパスワードを変更できる。パスワードを忘れた場合の再設定機能は無い。
- 管理者アカウントを追加したい場合は、管理者でログインし「利用者管理」画面から名前・メールアドレス・初期パスワードを入力して登録する。
